# SDAR v1.2.2 User Goal Runtime Design Freeze

Status: frozen implementation contract for EP-12

This document normalizes the v1.2.2 Master Goal, frozen decisions and AC-001–AC-078 into explicit
owners, identifiers, states and invariants. It does not change the authoritative SRS or Provider
Requirements Contract V0.5.2. Ambiguities remain governed by `AGENTS.md` and ADR-109.

## Authority map

| Concern | Owner | Not authority |
| --- | --- | --- |
| User Goal contract, Skill Goal DAG and layered outcome models | Domain | A2A/MCP/ORM/UI types |
| Planning, validation, scheduling, judges, recovery and terminal orchestration | Application | LangGraph internals or model prose |
| Immutable Workflow execution | LangGraph runtime | Skill Goal scheduler or event worker |
| Frozen MCP Tasks and Business Events wire | MCP adapter | Domain/Application |
| Plans, attempts, outcomes, budgets, effects, inbox/cursors and terminal commit | PostgreSQL | Redis, Console or SSE connection |
| Reconstructable dispatch/work queues | Redis/BullMQ | durable state |
| Operational projections and bounded actions | Management API/Console | lifecycle state machine |
| Business Event facts and candidate relations | external Provider | local impact/Goal outcome |

## Frozen identifiers

All local IDs are opaque, case-sensitive, 1–128 character ASCII strings unless an existing stricter
domain ID contract applies. New IDs are generated by the application and validated in Domain.

```text
UserGoalPlanId
SkillGoalId
SkillGoalDependencyId
SkillExecutionContractId
SkillAttemptId
TaskGoalContractId
OutcomeDecisionId
ProgressObservationId
CompletedEffectId
RecoveryDecisionId
BusinessEventSubscriptionId
BusinessEventInboxId
EventImpactAssessmentId
EventIncidentId
```

External `streamId`, `eventId`, `sequence`, `taskId`, `sourceId`, `resourceRef` and relation tokens keep
their frozen Provider V0.5.2 wire rules. Decimal sequences remain strings/`bigint`, never JavaScript
`number`.

## Frozen hashes

Hashes use RFC 8785 JCS canonical UTF-8 JSON and `sha256:<64 lowercase hex>` unless the external wire
defines another exact representation.

```text
userGoalContractHash
skillGoalContractHash
planContentHash
skillOutcomeSpecificationHash
executionContractHash
strategyFingerprint
effectFingerprint
evidenceFingerprint
artifactFingerprint
businessEventEnvelopeHash
relationProjectionHash
```

Hash input is a versioned object containing `schemaVersion`; identity, timestamps and mutable status are
excluded unless the named contract explicitly requires them. Secrets and credentials are never hashed
into displayable evidence.

## User Goal completion contract

```ts
interface UserGoalCompletionContract {
  goalId: string;
  goalVersion: number;
  title: string;
  description: string;
  constraints: readonly GoalConstraint[];
  criteria: readonly UserGoalCriterion[];
  assumptions: readonly GoalAssumption[];
  policy: GoalExecutionPolicy;
}
```

Every required criterion has a stable `criterionId`, expected effect/evidence/artifact shape and an
explicit required/optional classification. Required criterion coverage is exactly 100% before a plan is
accepted.

## User Goal Plan and Skill Goal DAG

Plan status:

```text
planning
validated
active
revision_pending
superseded
completed
failed
canceled
```

Revision kind:

```text
initial
goal_patch
user_revision
recovery
event_impact
```

Skill Goal status:

```text
pending
ready
dispatch_intent
selecting
executing
judging
achieved
partially_achieved
failed
blocked
superseded
canceled
```

A Skill Goal contains goal/version/plan identity, required result, capability needs, criterion coverage,
dependencies, effect/evidence/artifact requirements, assumptions and risk/policy constraints. It must
not contain Skill, Tool, Provider, MCP operation, Workflow or model-provider IDs.

Dependency predicates are `required` or `optional`. A required successor becomes ready only when every
required predecessor is `achieved`; `partially_achieved` never satisfies it.

Plan bounds are fixed:

```text
maxSkillGoals=16
maxDagDepth=8
maxParallelReadyGoals=4
maxPlanRevisions=4
maxPlanningModelAttempts=2
```

The validator rejects cycles, missing dependencies, duplicate IDs, disconnected required criteria,
required coverage below 100%, forbidden execution IDs, completed-effect reconstruction and every bound
violation.

## Skill outcome specification

Every enabled exact Skill version owns one immutable `SkillOutcomeSpecification`:

```ts
interface SkillOutcomeSpecification {
  effects: readonly EffectRequirement[];
  evidence: readonly EvidenceRequirement[];
  artifacts: readonly ArtifactRequirement[];
  taskGoalPolicy: TaskGoalPolicy;
  confidencePolicy: ConfidencePolicy;
  sideEffectPolicy: SideEffectPolicy;
}
```

Missing or invalid specification makes `enabled` illegal. Skill declaration/guidance is not evidence.
Compatibility admission checks capability, effect, evidence, artifact and policy before creating an
attempt.

## Skill execution contract and attempt

Attempt status:

```text
dispatch_intent
selecting
planning_workflow
awaiting_confirmation
running
waiting_external
judging
achieved
partially_achieved
failed
canceled
superseded
```

Only one active attempt may exist per Skill Goal. Replacement creates a new immutable attempt and keeps
the Skill Goal contract unchanged. An execution contract freezes exact Skill/version, resolved input,
required outcome specification, allowed Provider/Tool authority, budget, confirmation and no-replay
constraints. Workflow Plan/Instance and RemoteTaskBinding reference Skill Goal plus Attempt.

The scheduler transaction may create `dispatch_intent` under the Goal CAS. It commits before selection,
model calls, MCP/HTTP or queue operations. A later CAS operation advances or rejects the intent.

Safe parallelism requires disjoint side-effect/resource sets and policy permission. Unknown or
conflicting effects serialize conservatively. At most four ready safe Goals dispatch concurrently.

## Layered outcomes

Outcome level:

```text
task_goal
skill_goal
user_goal
```

Outcome status:

```text
achieved
partially_achieved
not_achieved
unknown
```

Confidence:

```text
high
medium
low
```

Rule evidence is evaluated before bounded semantic judgment. `low` confidence cannot produce
`achieved` or an impact decision of `none`. Every decision cites criterion/effect/evidence/artifact
references and records which deterministic rules ran.

The following are invariants:

```text
Provider Task completed does not imply Task Goal achieved.
Workflow completed does not imply Skill Goal achieved.
Skill Goal achieved does not imply User Goal achieved.
A2A completed if and only if User Goal outcome is achieved.
```

Only `UserGoalPlanController` may call the terminal repository. Its transaction locks the User Goal Plan,
User Goal, owning AgentTask and terminal authority row in a fixed order, applies CAS, inserts immutable
outcome evidence and projects one A2A terminal state. A uniqueness constraint resolves terminal races.

## Progress, budgets and recovery

Progress class:

```text
progressing
stalled
regressing
complete
```

The Progress Vector contains newly satisfied criteria/effects/evidence/artifacts, reduced uncertainty,
attempt/plan change and remaining budget. Percentage is display only and never terminal authority.

Budgets are persisted at Task, Workflow, Attempt and Plan levels. Counters are monotonic across restart.
`strategyFingerprint` covers the plan revision, Skill/version, Workflow strategy, input/effect target and
recovery action. A stalled recovery cannot repeat the same fingerprint.

Recovery checks authority in this order:

```text
User Goal already achieved
→ Skill Goal already achieved
→ Task Goal already achieved
→ uncertain remote Task reconcile
→ remaining budget and no-replay constraints
→ sibling/replacement attempt or plan revision
```

Completed Effect status is append-only `observed | verified | invalidated`; invalidation never erases
the original fact. Plan revisions inherit valid effects/evidence/artifacts and add their fingerprints to
Forbidden Replay. Emergency Skill execution is isolated and cannot complete the original Goal.

## Business Events client

Feature default is disabled. Adapter wire models are validated before conversion to Domain-owned client
records. Task Notification and Business Event subscription/cursor/state remain separate.

Client subscription generation status:

```text
current
draining_closed
reset_required
retired
```

Inbox processing status:

```text
admitted
processing
processed
retryable_failed
terminal_failed
```

`lastDurablyAdmittedSequence` advances only in the transaction that inserts/deduplicates the inbox row.
`lastProcessedSequence` advances independently after impact handling commits. Process failure cannot move
the admitted cursor backward. Duplicate event identity/hash mismatch fails closed.

Closed generations drain through `lastReplayableSequence`; continuity/reset creates an immutable
incident and conservative recovery fact. Relation result status is `complete | incomplete | expired |
authorization_mismatch | stream_reset`. Only `complete` can support a negative no-relation conclusion.

## Event impact and actions

Impact classification:

```text
none
current_task_goal
current_skill_goal
future_dependency
user_criterion
evidence_invalidated
plan_assumption_invalidated
continuity_unknown
cross_goal_incident
```

Rules have priority. A constrained semantic decision may choose only from supplied candidates; low
confidence cannot choose `none` or execute an action. Provider candidate relation is input evidence, not
impact authority.

Bounded actions:

```text
record_only
reconcile_remote_task
pause_attempt
cancel_attempt
insert_event_handling_skill_goal
revise_user_goal_plan
create_incident_task
request_confirmation
request_input
```

All side-effecting actions pass existing policy/confirmation. One-Goal necessary handling may insert an
EventHandlingSkillGoal. Cross-Goal or independent lifecycle facts create a deduplicated Incident AgentTask.
Continuity uncertainty cannot be normalized to task failure and always uses conservative recovery.

## Security and bounded data

- Every external JSON value is finite, cycle-free and bounded in depth, nodes, string bytes and total
  bytes before Domain entry.
- No LLM output, Skill package text, event payload or expression is evaluated/imported as source code.
- Credential values never enter Goal, plan, event, impact, metrics or reports.
- Metric labels never include Goal, Task, Event, resource, subscription or authorization identifiers.
- The trusted-intranet/no-auth warning remains visible; v1.2.2 adds no authentication authority.

## Acceptance ownership

The exact AC-to-code/test/report targets are in `docs/26_V1_2_2_TRACEABILITY.md`. Implementation may
rename a target symbol only when this design and traceability are updated in the same change. A frozen
invariant requires a superseding ADR, not an implicit code deviation.
