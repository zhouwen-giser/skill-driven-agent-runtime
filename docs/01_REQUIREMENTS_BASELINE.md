# 需求基线

本文件由《Agent通用模板Server需求规格说明书 V1.0》提取。原始 DOCX 是最高权威。本文件用于 Codex 搜索、追踪和自动检查。

需求总数：123；端到端验收场景：18。

| 需求编号 | 需求描述 | 验收要点 | 优先级 | 实施阶段 |
| --- | --- | --- | --- | --- |
| FR-A2A-001 | 系统必须作为 A2A Agent Provider，对任意兼容客户端提供服务；首版不得主动调用其他 A2A Agent。 | Agent Card 可发现；第三方兼容客户端可提交并继续任务。 | P0 | EP-01 |
| FR-A2A-002 | 协议版本锁定 A2A 1.0.1，优先使用官方 TypeScript SDK 实现协议对象、Agent Card、消息和任务生命周期。 | 协议契约测试通过；核心业务不修改官方状态枚举。 | P0 | EP-01 |
| FR-A2A-003 | A2A 层必须只使用标准任务状态；意图识别、计划生成、等待确认等内部阶段通过任务状态消息文本表达。 | 客户端只接收标准状态；消息中可读到当前阶段与等待原因。 | P0 | EP-01 |

| FR-A2A-011 | A2A 接口首版不实施认证，只允许部署于可信内网。 | 无凭据可调用；部署文档明确网络边界。 | P0 | EP-01 |
| FR-A2A-012 | A2A 中用户请求创建或修改 Skill 时，只生成 Skill 草案，不得直接发布。 | 草案可在管理端查看；Agent Card 不提前暴露。 | P0 | EP-01 |
| FR-GOAL-001 | 一个 context_id 必须维护一个持续推进的活动 Goal，多个 A2A Task 可共同推进该 Goal。 | 后续消息可继续、补充、修改、确认或取消当前 Goal。 | P0 | EP-04 |

## 端到端验收场景

| 场景 | 验收内容 |
| --- | --- |
| AC-01 基础任务闭环 | A2A 客户端提交目标；Agent 选择 Skill、生成计划、确认、调用 MCP、评估目标并返回文本与结构化结果。 |
| AC-02 自动确认 | 启用 auto_confirm_plan 的 Skill 生成合法计划后可直接执行；Goal 变更后仍必须重新确认。 |
| AC-03 计划修改 | A2A 客户端自然语言修改计划；管理端编辑 DAG/DSL；重新校验后执行。 |
| AC-04 多轮 Goal | 同一 context_id 中补充目标、修改约束、完成旧 Goal 后创建相关后续阶段或新 Goal。 |
| AC-05 Goal Patch 失效 | 部分执行后修改 Goal；旧 Workflow 和结果全部 invalidated，副作用按补偿策略处理，新计划重新确认。 |
| AC-06 Skill 组合 | 主 Workflow 通过 skill_call 调用子 Skill，使用执行时当前版本，并分别记录状态与评估。 |
| AC-07 能力缺口 | 无必要 MCP Tool 时进入 input-required/等待能力状态并返回清晰缺口；有 Tool 无 Skill 时生成临时 Skill。 |
| AC-08 外层重规划 | 首轮 Workflow 未达成 Goal，系统生成下一版计划并继续闭环；达到预算后终止。 |
| AC-09 工具异常 | MCP 调用失败，LLM 根据错误选择改参、重试、替代工具或终止，并保存决策记录。 |
| AC-10 暂停恢复取消 | 验证尝试中断、节点边界暂停、短暂停恢复、长暂停重新规划、取消默认策略和等待超时取消。 |
| AC-11 队列与故障 | 同 context 串行；待执行任务重启后保留；执行中任务崩溃后失败且不重试。 |
| AC-12 Skill 注册 | 自然语言描述经 LLM 生成 input/output Schema；不合法时注册失败。 |
| AC-13 Skill 自动演化 | 相似成功经验达到阈值，归纳候选 Skill，完成回放和补充测试，全部通过后自动发布。 |
| AC-14 人工修正 | 验证失败草案由管理员修正后重试，修正记录进入演化经验。 |
| AC-15 Prompt 演化 | 系统生成候选 Prompt 版本，未发布前不生效；管理员发布后新调用关联新版本。 |
| AC-16 记忆与检索 | 完整轨迹归档，提炼记忆可按阶段检索；记忆支持 superseded/invalid。 |
| AC-17 管理控制台 | 完成 MCP、Skill、Prompt、任务、Workflow、记忆、评估、回放和运营分析全流程。 |
| AC-18 A2A 流式 | 标准事件流可展示状态更新；连接断开后任务继续，轮询可获得最终结果。 |
