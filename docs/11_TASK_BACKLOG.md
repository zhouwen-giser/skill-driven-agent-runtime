# 项目任务 Backlog

所有任务完成状态最终以 Traceability Matrix 和自动化证据为准。

## EP-00 仓库初始化与兼容性基线

## EP-01 协议与领域骨架

- [ ] **FR-A2A-001** 系统必须作为 A2A Agent Provider，对任意兼容客户端提供服务；首版不得主动调用其他 A2A Agent。  
  验收：Agent Card 可发现；第三方兼容客户端可提交并继续任务。

- [ ] **FR-A2A-002** 协议版本锁定 A2A 1.0.1，优先使用官方 TypeScript SDK 实现协议对象、Agent Card、消息和任务生命周期。  
  验收：协议契约测试通过；核心业务不修改官方状态枚举。

- [ ] **FR-A2A-003** A2A 层必须只使用标准任务状态；意图识别、计划生成、等待确认等内部阶段通过任务状态消息文本表达。  
  验收：客户端只接收标准状态；消息中可读到当前阶段与等待原因。

- [ ] **FR-A2A-004** 必须支持任务提交、状态查询、取消、最终结果获取、计划确认、补充输入、多轮上下文、暂停和恢复。  
  验收：每种操作均有端到端测试。

- [ ] **FR-A2A-005** 必须同时支持非流式响应与标准流式事件；流式连接中断不得终止任务。  
  验收：断流后任务继续；可重连或轮询获取状态。

- [ ] **FR-A2A-006** Agent Card 必须动态映射当前启用 Skill；Skill 新增、更新、禁用后自动刷新能力声明。  
  验收：Agent Card 与启用 Skill 列表一致。

- [ ] **FR-A2A-007** user_id 应从 A2A metadata 读取且可选；缺省时使用固定 anonymous。  
  验收：不传 user_id 可执行；记录归属 anonymous。

- [ ] **FR-A2A-008** context_id 可选；缺省时自动创建并在响应中返回。  
  验收：首次请求获得新 context_id；后续携带后可延续会话。

- [ ] **FR-A2A-009** 同一 context_id 下的活动任务必须严格串行，后续任务进入 Redis 队列。  
  验收：并发提交不会并行修改同一会话。

- [ ] **FR-A2A-010** 最终结果必须同时包含自然语言结果与符合 Skill output_schema 的结构化数据。  
  验收：文本与结构化结果均存在且 Schema 校验通过。

- [ ] **FR-A2A-011** A2A 接口首版不实施认证，只允许部署于可信内网。  
  验收：无凭据可调用；部署文档明确网络边界。

- [ ] **FR-A2A-012** A2A 中用户请求创建或修改 Skill 时，只生成 Skill 草案，不得直接发布。  
  验收：草案可在管理端查看；Agent Card 不提前暴露。

## EP-02 MCP 与 Skill 基础

- [ ] **FR-SKL-001** Skill 必须采用轻量 Schema + 自然语言描述，描述其能力、适用目标、流程提示、输出方式和运行策略。  
  验收：管理端可创建和编辑；版本内容完整。

- [ ] **FR-SKL-002** Skill 注册时必须由 LLM 自动生成 input_schema 与 output_schema；生成结果必须为合法 JSON Schema。  
  验收：Schema 校验通过后才能注册。

- [ ] **FR-SKL-003** 若 LLM 无法生成合法或足够明确的 Schema，注册必须失败并要求补充描述。  
  验收：不存在宽松兜底 Schema 或未校验发布。

- [ ] **FR-SKL-004** Skill 必须支持 required_tools、optional_tools、forbidden_tools 三类 MCP Tool 权限边界。  
  验收：规划器不得违反禁止工具；必要工具缺失可被识别。

- [ ] **FR-SKL-005** Skill 必须支持 auto_confirm_plan、预算、取消策略、补偿策略和暂停重规划阈值等运行配置。  
  验收：相关配置影响任务运行。

- [ ] **FR-SKL-006** Skill 必须版本化，每次修改生成新版本；自动演化的新版本验证通过后立即成为当前生效版本，旧版本可回滚。  
  验收：版本链、来源、差异、回滚均可查看。

- [ ] **FR-SKL-007** Skill 必须支持 enabled/disabled；禁用后不得被新任务选择，并从 Agent Card 移除。  
  验收：禁用即时生效。

- [ ] **FR-SKL-008** 所有用户创建或自动沉淀的正式 Skill 默认进入全局共享库。  
  验收：不同 user_id 可检索和使用同一 Skill。

- [ ] **FR-SKL-009** 系统必须维护 Skill 图谱，包括父子、依赖、输入输出匹配、替代、组合和能力覆盖关系。  
  验收：管理端可查看图谱；规划器可使用关系信息。

- [ ] **FR-SKL-010** Workflow 调用其他 Skill 时必须保留 skill_call 节点，并在运行时生成独立子工作流。  
  验收：子 Skill 具有独立状态、版本和评估记录。

- [ ] **FR-SKL-011** skill_call 执行时必须使用子 Skill 当前生效版本，并记录实际版本。  
  验收：执行记录可追溯具体版本。

- [ ] **FR-SKL-012** 多个 Skill 均能满足目标时，LLM 必须综合语义匹配、成功率、耗时、成本、失败记录和稳定性选择。  
  验收：选择理由和指标快照可查看。

- [ ] **FR-SKL-013** 首选 Skill 失败且存在替代 Skill 时，系统必须生成替代计划并重新请求确认。  
  验收：不得自动无确认切换并执行。

- [ ] **FR-SKL-014** MCP Tool 已具备但没有正式 Skill 时，Agent 可生成仅限当前任务的临时 Skill。  
  验收：临时 Skill 可执行但不进入正式库。

- [ ] **FR-SKL-015** 临时 Skill 在任务结束后失效，只保存为执行经验；达到重复成功阈值后再归纳为正式 Skill。  
  验收：正式库中不出现单次成功直接发布的临时 Skill。

- [ ] **FR-MCP-001** 首版只支持远程 MCP Server，不支持本地 stdio。  
  验收：注册界面只提供远程传输配置。

- [ ] **FR-MCP-002** 必须定义统一 MCP Transport Adapter，首版实现 Streamable HTTP，允许后续扩展其他远程传输。  
  验收：业务层不直接依赖具体传输。

- [ ] **FR-MCP-003** 首版只发现、注册和调用 MCP Tools，不支持 Resources 与 Prompts。  
  验收：能力清单中不存在 Resources/Prompts。

- [ ] **FR-MCP-004** MCP Server 必须支持运行时注册、删除和手动刷新；注册即视为可信，不实施权限审批。  
  验收：无需重启即可生效。

- [ ] **FR-MCP-005** 注册时发现一次 Tool 清单和 Schema；后续变化仅由管理员手动刷新。  
  验收：无定时自动刷新任务。

- [ ] **FR-MCP-006** 每个 MCP Server 使用注册级固定凭据，所有任务共享。  
  验收：调用时使用注册凭据。

- [ ] **FR-MCP-007** MCP 凭据必须加密后存入 PostgreSQL，由统一主密钥解密。  
  验收：数据库中不存在明文密钥。

- [ ] **FR-MCP-008** Tool 注册时由 LLM 自动增强用途、场景、约束、返回说明、常见错误和标签，管理员可编辑。  
  验收：增强元数据可见且参与规划。

- [ ] **FR-MCP-009** 实际调用必须始终以 MCP 原始 input schema 为权威，增强元数据不得改变调用契约。  
  验收：调用前按原始 Schema 校验。

- [ ] **FR-MCP-010** Skill 只引用 MCP Server 和 Tool 名称，执行时使用当前注册定义，不锁定工具快照。  
  验收：刷新后执行使用新定义。

- [ ] **FR-MCP-011** 工具删除或 Schema 变化影响 Skill 时，只产生依赖告警，Skill 仍保持启用。  
  验收：管理端显示告警；不会自动禁用。

- [ ] **FR-MCP-012** MCP 调用失败时由 LLM 动态决定重试、改参、替代工具、调用其他 Skill 或终止。  
  验收：异常决策记录可回放。

- [ ] **FR-MCP-013** 首版不提供副作用工具的幂等键、重复调用保护或逐次确认。  
  验收：系统不得声称运行时自动去重。

## EP-03 Workflow 规划与运行时

- [ ] **FR-LLM-001** 必须定义统一 ModelProvider 接口，支持多个 OpenAI 兼容服务、本地模型和其他厂商模型。  
  验收：新增 Provider 不影响核心决策接口。

- [ ] **FR-LLM-002** 模型路由按任务阶段固定配置，不按成本、复杂度或可用性动态选择。  
  验收：意图、Skill、规划、执行决策、评估等阶段可分别配置模型。

- [ ] **FR-LLM-003** 阶段模型不可用、超时或失败时，当前任务直接失败，不切换备用模型。  
  验收：无隐式 fallback；错误信息明确。

- [ ] **FR-LLM-004** 意图、目标、Skill 选择、Workflow 生成、异常决策和目标评估的最终裁决必须由 LLM 完成。  
  验收：规则/检索只提供候选和约束，不直接裁决。

- [ ] **FR-LLM-005** Skill、历史经验和长期记忆应使用元数据与 pgvector 检索形成上下文，但不得替代 LLM 最终选择。  
  验收：可查看检索结果与最终决策。

- [ ] **FR-LLM-006** 各阶段 Prompt 必须数据库配置化、版本化、可启停、可回滚并记录效果。  
  验收：Prompt 版本与模型调用可关联。

- [ ] **FR-LLM-007** 系统可根据失败案例和评估自动生成候选 Prompt 版本，但必须由管理员发布后才能生效。  
  验收：自动候选不直接切换生产版本。

- [ ] **FR-LLM-008** 后台必须保存模型请求、上下文、模型原始响应、模型版本、Token 用量和耗时；A2A 不返回模型内部隐式推理过程。  
  验收：管理端可审查结构化决策和调用记录。

- [ ] **FR-WF-001** LLM 必须输出符合 JSON Schema 的结构化 Workflow DSL，不得生成并动态执行 TypeScript 代码。  
  验收：所有执行图均可序列化、验证和审计。

- [ ] **FR-WF-002** DSL 必须支持 LLM、MCP Tool、结果输出、条件分支、并行、循环、子工作流、人工确认、异常处理和 skill_call 节点。  
  验收：每类节点均有编译和执行测试。

- [ ] **FR-WF-003** DSL 校验必须覆盖 JSON Schema、节点唯一性、边引用、入口出口、循环边界、工具存在性和工具参数 Schema。  
  验收：无效图不能进入执行。

- [ ] **FR-WF-004** DSL 校验失败时，必须将错误反馈给原规划模型，在配置次数内自动修正；超过次数任务失败。  
  验收：修正次数和失败草案被保存。

- [ ] **FR-WF-005** 自动修正通过后的 DSL 可直接作为已确认计划执行，不再次要求确认。  
  验收：纯自动修正不会产生第二次确认。

- [ ] **FR-WF-006** 首版固定使用 LangGraph.js 作为 Workflow Engine，并由编译器将 DSL 转换为 StateGraph。  
  验收：执行图不依赖其他 Agent Runtime。

- [ ] **FR-WF-007** 单次 Workflow 执行期间图结构保持不变；运行中不得直接增删后续节点。  
  验收：结构变化只能通过外层新 Workflow 实现。

- [ ] **FR-WF-008** Workflow 完成、失败或触发特定条件后，外层控制器可基于最新状态生成下一版 Workflow。  
  验收：重规划轮次可追踪。

- [ ] **FR-WF-009** 每个 Skill 可配置最大重规划轮次、执行时长、LLM/MCP 调用次数和费用预算，缺省使用系统值。  
  验收：任一预算达到后按终止策略结束。

- [ ] **FR-WF-010** 普通 A2A 客户端可用自然语言修改计划；管理端可直接编辑 DSL 或可视化 DAG，校验后执行。  
  验收：两种修改入口均可用。

## EP-04 任务生命周期与 Goal 闭环

- [ ] **FR-GOAL-001** 一个 context_id 必须维护一个持续推进的活动 Goal，多个 A2A Task 可共同推进该 Goal。  
  验收：后续消息可继续、补充、修改、确认或取消当前 Goal。

- [ ] **FR-GOAL-002** 当前 Goal 结束后，LLM 必须判断新请求与旧 Goal 的相关性；相关则创建后续阶段，不相关则创建新 Goal。  
  验收：Goal 关系和历史可查询。

- [ ] **FR-GOAL-003** Goal 更新必须先生成结构化 Goal Patch，并重新审议 Skill、计划和已有结果。  
  验收：保存 Patch 类型、字段变化和模型决策摘要。

- [ ] **FR-GOAL-004** Goal Patch 生效后，当前 Workflow、已完成步骤和中间结果必须全部作废，不允许复用。  
  验收：相关对象标记 invalidated，后续计划不引用旧结果。

- [ ] **FR-GOAL-005** Goal 变更后的新计划必须重新确认，不受 Skill 自动确认配置影响。  
  验收：未经新确认不得执行。

- [ ] **FR-GOAL-006** 缺少输入时 Agent 必须先结合会话历史、全局长期记忆和已有数据自主推断；无法可靠推断时进入 input-required。  
  验收：可解释记录推断来源；无法推断时返回明确问题。

- [ ] **FR-GOAL-007** 等待计划确认或补充输入使用系统统一超时；超时后任务自动取消并保留记录。  
  验收：超时配置可管理；任务状态与审计记录正确。

- [ ] **FR-GOAL-008** 用户主动取消 Goal 或任务时，必须停止后续规划和执行，并按取消策略处理当前节点。  
  验收：取消后无新节点启动。

- [ ] **FR-EXE-001** 默认采用规划—执行分离：计划生成并校验后进入确认；Skill 可配置自动确认。  
  验收：未自动确认的任务不会提前调用 MCP。

- [ ] **FR-EXE-002** 计划确认同时支持 A2A 后续消息和管理 API；可确认、拒绝或提出修改。  
  验收：两类入口状态一致。

- [ ] **FR-EXE-003** 任务执行支持同步/异步混合：短任务可等待返回，复杂任务返回任务标识并继续执行。  
  验收：两类调用均可获得一致状态与最终结果。

- [ ] **FR-EXE-004** 任务暂停时先尝试中断当前 LLM/MCP 节点；无法中断则等待节点结束后暂停。  
  验收：暂停期间不启动后续节点。

- [ ] **FR-EXE-005** 恢复时若暂停时长未超过 Skill 阈值则从暂停位置继续；超过阈值则重新规划并重新确认。  
  验收：Skill 阈值覆盖全局默认值。

- [ ] **FR-EXE-006** 用户取消任务时优先使用 Skill cancel_policy；未定义时尝试中断当前调用，无法中断则等待结束并停止后续节点。  
  验收：取消后状态终结且不自动补偿。

- [ ] **FR-EXE-007** Goal 变更引发的副作用补偿必须按 Skill compensation_policy 生成并纳入新的待确认计划。  
  验收：无策略时仅告警，不自动撤销。

- [ ] **FR-EXE-008** 执行中进程崩溃、Worker 异常或 Redis 运行态丢失时，任务必须标记失败，不恢复、不自动重试。  
  验收：不会重复调用 MCP。

- [ ] **FR-EXE-009** BullMQ 队列层不得自动重试失败任务；客户端需重新提交。  
  验收：attempts 配置为 1 或等效机制。

- [ ] **FR-EXE-010** 排队但尚未执行的任务必须持久化在 Redis，服务重启后可继续调度。  
  验收：重启后待执行任务仍存在。

- [ ] **FR-RST-001** MCP 返回必须经过统一标准化、错误归一化、Schema 校验、摘要和上下文裁剪。  
  验收：下游节点接收统一结果封装。

- [ ] **FR-RST-002** 结果处理层必须提取关键事实、判断结果价值，并形成可写入长期记忆的候选内容。  
  验收：结果可关联事实和记忆记录。

- [ ] **FR-RST-003** 最终输出必须由 LLM 按 Skill 输出说明生成自然语言，同时产出符合 output_schema 的结构化数据。  
  验收：两种输出语义一致。

- [ ] **FR-RST-004** 一次 Workflow 结束不得自动等同于 Goal 完成，必须进入目标达成评估。  
  验收：每轮执行均有 Outcome Evaluation。

- [ ] **FR-RST-005** 目标未达成时必须判断补充信息、调整计划、替代 Skill、调用其他 Skill或终止。  
  验收：每种决策均有明确状态与理由。

- [ ] **FR-RST-006** 存在必要 MCP 能力缺口时，任务进入等待状态并返回所需工具能力说明。  
  验收：客户端可读到缺失能力和建议工具契约。

## EP-05 记忆、评估与演化

- [ ] **FR-EVO-001** 单次成功任务必须先保存为经验，不得直接生成正式 Skill。  
  验收：经验记录包含目标、工具组合、Workflow、结果和评估。

- [ ] **FR-EVO-002** 相似成功经验达到可配置最小次数后，LLM 才可判断是否归纳 Skill。  
  验收：阈值可配置且有触发日志。

- [ ] **FR-EVO-003** LLM 必须判断经验的一致性、稳定性、通用性和与现有 Skill 的重复程度。  
  验收：归纳报告可查看。

- [ ] **FR-EVO-004** 能力边界相同但执行方式改进时创建原 Skill 新版本；能力边界显著不同则创建新 Skill。  
  验收：合并或新建理由可追踪。

- [ ] **FR-EVO-005** 自动发布前必须执行静态验证、历史成功/失败任务回放和 LLM 补充的正常、边界、异常测试。  
  验收：验证报告列出全部用例和结果。

- [ ] **FR-EVO-006** 所有模拟用例必须全部通过才能自动发布；任何失败均保留为草案。  
  验收：验证失败不会改变当前生效版本。

- [ ] **FR-EVO-007** 管理员可人工修正失败草案后重新验证；人工修正内容必须作为后续演化经验。  
  验收：修正记录、修改人、差异、验证结果可追溯。

- [ ] **FR-EVO-008** 系统自动归纳或演化产生的 Skill 验证通过后可自动发布；用户通过 A2A 请求的 Skill 草案必须由管理端发布。  
  验收：按来源应用不同发布策略。

- [ ] **FR-EVO-009** Skill 连续低评分或失败率升高时只能产生质量告警，不得自动禁用或自动修复。  
  验收：告警可见，Skill 仍保持启用。

- [ ] **FR-EVO-010** 高频成功动态 Workflow 应可自动沉淀为 Workflow Template，供后续相似任务优先复用并调整。  
  验收：模板来源、版本和使用效果可追踪。

- [ ] **FR-MEM-001** 长期记忆默认全局共享，所有用户的事实、成功经验、失败经验和执行经验可被后续任务检索。  
  验收：跨 user_id 检索可命中共享记忆。

- [ ] **FR-MEM-002** PostgreSQL 保存完整原始任务和执行轨迹；长期记忆仅保存经 LLM 提炼、去重和结构化的内容，并引用原任务。  
  验收：记忆可回溯原始证据。

- [ ] **FR-MEM-003** 长期记忆检索必须按阶段区分：意图、Skill 选择、Workflow 生成、异常处理和目标评估。  
  验收：每个阶段使用对应记忆类型与查询模板。

- [ ] **FR-MEM-004** 记忆必须支持 active、superseded、invalid 等状态以及替代关系，历史记录不得物理覆盖。  
  验收：冲突和过期记忆可版本化管理。

- [ ] **FR-MEM-005** Skill 人工修正、Prompt 修正、失败原因和评估结论必须可作为演化经验写入记忆。  
  验收：后续生成可检索这些经验。

- [ ] **FR-MEM-006** 首版不自动清理历史数据，但必须预留归档、删除和保留策略配置。  
  验收：管理 API 和模型中存在保留策略字段。

- [ ] **FR-EVAL-001** 任务完成后必须由目标评估器、Workflow 评估器、Skill 评估器、结果质量评估器和工具调用评估器交叉评价。  
  验收：形成结构化任务质量报告。

- [ ] **FR-EVAL-002** 用户反馈首版采用隐式行为判断，包括接受结果、继续修改、重复提交、要求重做或切换 Skill。  
  验收：隐式反馈标注低置信度并关联任务。

- [ ] **FR-EVAL-003** 评估结果必须参与 Skill 演化、Workflow Template 沉淀和候选 Prompt 优化。  
  验收：演化记录引用评估报告。

- [ ] **FR-EVAL-004** 管理端必须展示成功率、耗时、调用成本、失败类型、版本稳定性和质量趋势。  
  验收：可按 Skill/版本/模型/工具筛选。

- [ ] **FR-EVAL-005** 低质量 Skill 只告警，不自动禁用；管理员可自行禁用、回滚或修正。  
  验收：告警和操作入口存在。

## EP-06 管理控制台与可观测性

- [ ] **FR-ADM-001** 首版管理 API 与控制台不认证，仅限可信内网。  
  验收：无需登录可访问；部署说明包含风险警告。

- [ ] **FR-ADM-002** 必须支持 MCP Server 注册、删除、手动刷新、健康检查、工具查看、凭据更新和元数据编辑。  
  验收：完整 CRUD 与操作日志可用。

- [ ] **FR-ADM-003** 必须支持 Skill 草案、Schema 生成、编辑、模拟验证、发布、版本对比、回滚、启停、图谱和告警。  
  验收：全部生命周期可操作。

- [ ] **FR-ADM-004** 必须支持 Workflow DAG 展示、可视化编辑、DSL 编辑、校验、计划确认、节点状态和执行回放。  
  验收：任务可从计划到轨迹完整回放。

- [ ] **FR-ADM-005** 必须支持 Prompt 版本、候选优化、发布、回滚和效果对比。  
  验收：Prompt 变更可追踪。

- [ ] **FR-ADM-006** 必须支持任务、会话、Goal、模型调用、MCP 调用、执行事件、结果、评估和错误日志查询。  
  验收：支持关联导航和筛选。

- [ ] **FR-ADM-007** 必须支持长期记忆查看、检索、状态变更、替代关系和来源追溯。  
  验收：可管理 active/superseded/invalid。

- [ ] **FR-ADM-008** 必须提供 Skill 效果分析、版本趋势、MCP 使用分析、模型效果评估、能力成长和自动优化建议。  
  验收：运营仪表板可展示关键指标。

## EP-07 加固与完整验收

- [ ] **NFR-PERF-001** 单实例支持约 1～10 个并发活动任务；同 context_id 严格串行。  
  验收：并发测试中系统稳定，无会话状态交叉。

- [ ] **NFR-PERF-002** 队列、模型调用、MCP 调用和 Workflow 节点必须记录耗时，支持定位长耗时阶段。  
  验收：管理端可展示分阶段耗时。

- [ ] **NFR-REL-001** 待执行任务使用 Redis/BullMQ 持久化；执行中状态只在 Redis 保证运行期可用。  
  验收：重启后待执行任务存在，执行中任务失败。

- [ ] **NFR-REL-002** 任务故障、队列 Worker 异常和模型失败不得自动重试整个任务。  
  验收：不会因系统策略重复产生副作用。

- [ ] **NFR-SEC-001** 首版无接口认证与权限控制，必须明确标注仅可信内网部署。  
  验收：部署检查包含网络隔离项。

- [ ] **NFR-SEC-002** MCP 和模型密钥必须加密存储，主密钥独立于数据库。  
  验收：安全检查无明文凭据。

- [ ] **NFR-OBS-001** 任务、节点、模型、MCP、状态变化、计划确认、Goal Patch 和评估必须具有关联追踪标识。  
  验收：可从任务导航到全链路记录。

- [ ] **NFR-OBS-002** A2A 只返回必要过程摘要，不返回模型内部隐式推理；管理端可查看结构化决策、Prompt 与原始响应。  
  验收：对外输出不含隐藏推理。

- [ ] **NFR-MNT-001** A2A、MCP Transport、ModelProvider、存储和 Workflow Compiler 必须模块化，便于后续扩展。  
  验收：接口边界可单元测试。

- [ ] **NFR-COMP-001** 首版仅保证 A2A 1.0.1，不承担多版本协议兼容。  
  验收：协议测试以 1.0.1 为唯一基线。

- [ ] **NFR-DATA-001** 首版历史数据默认持续保存，不自动清理。  
  验收：无自动删除任务；保留策略字段已预留。

- [ ] **NFR-UX-001** 管理控制台必须支持从任务、Goal、Skill、Workflow、Tool、模型、记忆和评估之间双向导航。  
  验收：主要对象一键关联跳转。
