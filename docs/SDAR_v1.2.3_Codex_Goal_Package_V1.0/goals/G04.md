## 必须完成的实施任务

1. 实现 UNDERSTAND→GOAL_REVIEW 状态机。
2. 实现 `MissingDimensionQuestionService`，按信息增益选择问题。
3. 每轮绑定 Dimension、Criterion、阻断原因、Understanding Version。
4. 支持 answer、accept、patch、reject、restart_understanding、cancel。
5. 用户回答后创建新的 Understanding Revision，不修改旧版本。
6. 实现 Candidate User Goal Completion Contract 生成和 Diff。
7. 实现 `sessionId + expectedVersion + idempotencyKey` CAS。
8. 映射 A2A `input-required` 和 `io.sdar/interaction` Metadata。
9. 设置 maxClarificationRounds、maxContractRevisions 和 elapsed budget。

## 实施细则

- 先审计当前仓库符号和测试，禁止创建重复服务或第二权威；
- 所有新 Domain 对象必须有 factory/validator、immutable snapshot 和明确 error code；
- 所有模型输出必须使用 Zod/JSON Schema，并由确定性 Application 代码校验；
- PostgreSQL 写入必须定义事务、CAS/幂等和重启语义；
- Redis/BullMQ 数据必须可由 PostgreSQL 重建；
- 适合时先加入失败测试，再完成实现；
- 更新 OpenAPI、Acceptance Map、Architecture、Migration 和 Console（如本 Goal 涉及）；
- 不允许 TODO、空实现、仅接口或只在测试环境生效的产品路径。

## 禁止事项

- 不改写 v1.2.2 Goal/Skill/Outcome/Recovery Authority；
- 不让 LLM 直接写权威状态；
- 不保存私有思维链；
- 不引入 Python Sidecar 或文件型知识权威；
- 不让 Candidate 绕过 Promotion；
- 不自动发布 Skill；
- 不删除失败测试或降低冻结验收标准；
- 不修改与本 Goal 无关的功能，除非为修复真实架构阻断并记录 ADR。

## 验证

- 并发回答只有一个成功，冲突返回最新 Snapshot。
- 重复 idempotencyKey 不重复写入。
- 已回答维度不重复询问。
- 达到预算后停止。
- 未确认 Contract 不进入 Planning。

最低还必须运行受影响范围的 format、lint、typecheck、unit、contract、integration 和 build；最终完整 `pnpm verify` 在 G17 执行。
