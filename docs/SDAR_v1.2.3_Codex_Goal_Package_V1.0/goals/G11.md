## 必须完成的实施任务

1. 从 Skill Outcome、Attempt、Evidence、Artifact、Correction、Recovery 和 Event Impact 归纳能力模式。
2. 区分 Declared、Observed、Validated Capability。
3. 保存 Applicable Conditions、Effect、Evidence、Artifact、Prerequisite、Dependency、Failure 和 Limitation。
4. 映射精确 Skill Version；映射为空时创建 Capability Gap Candidate。
5. Skill Catalog Hash、Skill Version 或 Policy 变化触发重新验证。
6. Gap 可产生 Skill Authoring Proposal，但不得自动发布 Skill。

## 实施细则

- 先审计当前仓库符号和测试，禁止创建重复服务或第二权威；
- 所有新 Domain 对象必须有 factory/validator、immutable snapshot 和明确 error code；
- 所有模型输出必须使用 Zod/JSON Schema，并由确定性 Application 代码校验；
- PostgreSQL 写入必须定义事务、CAS/幂等和重启语义；
- Redis/BullMQ 数据必须可由 PostgreSQL 重建；
- 适合时先加入失败测试，再完成实现；
- 更新 OpenAPI、Acceptance Map、Architecture、Migration 和 Console（如本 Goal 涉及）；
- 不允许 TODO、空实现、仅接口或只在测试环境生效的产品路径。

## 禁止事项

- 不改写 v1.2.2 Goal/Skill/Outcome/Recovery Authority；
- 不让 LLM 直接写权威状态；
- 不保存私有思维链；
- 不引入 Python Sidecar 或文件型知识权威；
- 不让 Candidate 绕过 Promotion；
- 不自动发布 Skill；
- 不删除失败测试或降低冻结验收标准；
- 不修改与本 Goal 无关的功能，除非为修复真实架构阻断并记录 ADR。

## 验证

- Observed Capability 不修改 Skill 声明。
- 过去成功不绕过当前 Readiness。
- Skill Version 变化使相关 Active Pattern 进入 validating。
- 无 Skill 映射正确形成 Gap。

最低还必须运行受影响范围的 format、lint、typecheck、unit、contract、integration 和 build；最终完整 `pnpm verify` 在 G17 执行。
