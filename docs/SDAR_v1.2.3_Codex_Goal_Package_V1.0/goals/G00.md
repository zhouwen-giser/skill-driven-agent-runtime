## 必须完成的实施任务

1. 批准 KD-01～KD-20，并建立 ADR 编号、责任人和替代关系。
2. 冻结 Experience、Capability、Task Understanding、Interactive Session、Knowledge Promotion 的 Domain Schema。
3. 定义 Candidate/Active、Declared/Observed/Validated、task/user/tenant/global_candidate 等术语。
4. 建立所有状态机、错误码、Reason Code、Source Authority 和数据分类。
5. 定义 Cognitive Runtime Ports，确保 `domain` 不依赖 `application/persistence/a2a`。
6. 建立 Feature Flag、Model Stage、Outbox Event、Queue Name 和 Correlation ID 常量。
7. 建立第三方来源锁：仓库、commit、审计路径、reuseType、许可证和 NOTICE 义务。
8. 新增架构检查，禁止 v1.2.2 Runtime 反向依赖 Experience/Task Type/Capability Pattern。
9. 制定开发态数据库重置规则：不迁移未发布实验数据，但保留 v1.2.3 内部不可变版本语义。

## 实施细则

- 先审计当前仓库符号和测试，禁止创建重复服务或第二权威；
- 所有新 Domain 对象必须有 factory/validator、immutable snapshot 和明确 error code；
- 所有模型输出必须使用 Zod/JSON Schema，并由确定性 Application 代码校验；
- PostgreSQL 写入必须定义事务、CAS/幂等和重启语义；
- Redis/BullMQ 数据必须可由 PostgreSQL 重建；
- 适合时先加入失败测试，再完成实现；
- 更新 OpenAPI、Acceptance Map、Architecture、Migration 和 Console（如本 Goal 涉及）；
- 不允许 TODO、空实现、仅接口或只在测试环境生效的产品路径。

## 禁止事项

- 不改写 v1.2.2 Goal/Skill/Outcome/Recovery Authority；
- 不让 LLM 直接写权威状态；
- 不保存私有思维链；
- 不引入 Python Sidecar 或文件型知识权威；
- 不让 Candidate 绕过 Promotion；
- 不自动发布 Skill；
- 不删除失败测试或降低冻结验收标准；
- 不修改与本 Goal 无关的功能，除非为修复真实架构阻断并记录 ADR。

- 架构依赖扫描。

最低还必须运行受影响范围的 format、lint、typecheck、unit、contract、integration 和 build；最终完整 `pnpm verify` 在 G17 执行。
