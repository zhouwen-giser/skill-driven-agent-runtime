## 必须完成的实施任务

1. 实现 `CapabilityCatalogSnapshotBuilder`，按精确 Skill Version 收集权威声明。
2. 定义 Canonical JSON 和排序规则，生成稳定 `catalogHash`。
3. 实现 Capability、Domain、Effect、Evidence、Artifact、Context、Mode、Task Type 和 Composition 聚合。
4. 实现 Capability Limitation：缺 Outcome、仅内部、需确认、不可组合、无 Enabled Skill 等。
5. 实现 Active Summary Pointer 和按 Hash 幂等重建。
6. 订阅 Skill Enable/Disable、Version、Outcome Specification、Visibility 和 Composition 变化。
7. 构建 Level-0 Capability Index 与 Level-1 Detail，Level-2 Exact Skill 延迟到 Skill Selection。
8. 实现 Cache 和 Hash-matched Snapshot 读取；禁止写入动态 Readiness。

## 实施细则

- 先审计当前仓库符号和测试，禁止创建重复服务或第二权威；
- 所有新 Domain 对象必须有 factory/validator、immutable snapshot 和明确 error code；
- 所有模型输出必须使用 Zod/JSON Schema，并由确定性 Application 代码校验；
- PostgreSQL 写入必须定义事务、CAS/幂等和重启语义；
- Redis/BullMQ 数据必须可由 PostgreSQL 重建；
- 适合时先加入失败测试，再完成实现；
- 更新 OpenAPI、Acceptance Map、Architecture、Migration 和 Console（如本 Goal 涉及）；
- 不允许 TODO、空实现、仅接口或只在测试环境生效的产品路径。

## 禁止事项

- 不改写 v1.2.2 Goal/Skill/Outcome/Recovery Authority；
- 不让 LLM 直接写权威状态；
- 不保存私有思维链；
- 不引入 Python Sidecar 或文件型知识权威；
- 不让 Candidate 绕过 Promotion；
- 不自动发布 Skill；
- 不删除失败测试或降低冻结验收标准；
- 不修改与本 Goal 无关的功能，除非为修复真实架构阻断并记录 ADR。

## 验证

- 同一 Skill 集合生成相同 Hash 的 Property Test。
- 输入顺序变化不影响 Hash。
- Skill 版本/可见性变化必然改变 Hash。
- Summary 不包含 Provider 当前状态。
- 并发重建只激活一个匹配 Snapshot。

最低还必须运行受影响范围的 format、lint、typecheck、unit、contract、integration 和 build；最终完整 `pnpm verify` 在 G17 执行。
