## 必须完成的实施任务

1. 构建 Query Fingerprint 和结构化 Scope/Status/Applicability/Catalog/Policy Filter。
2. 并行 Vector Recall 与 Text/FTS Recall，使用 RRF 融合。
3. 实现关系一跳扩展：requires、contradicts、supersedes、supported_by、related。
4. 按 Planning Session 记录已使用 Knowledge ID，避免重复注入。
5. Level-0 Index→Top-K Full Definition→Exact Skill 的渐进加载。
6. 实现默认预算：Task Type 3、Capability 8、Heuristic 8、总字符20K。
7. 冲突知识不合并；低置信度和版本不匹配剔除。
8. P95 目标≤500ms。

## 实施细则

- 先审计当前仓库符号和测试，禁止创建重复服务或第二权威；
- 所有新 Domain 对象必须有 factory/validator、immutable snapshot 和明确 error code；
- 所有模型输出必须使用 Zod/JSON Schema，并由确定性 Application 代码校验；
- PostgreSQL 写入必须定义事务、CAS/幂等和重启语义；
- Redis/BullMQ 数据必须可由 PostgreSQL 重建；
- 适合时先加入失败测试，再完成实现；
- 更新 OpenAPI、Acceptance Map、Architecture、Migration 和 Console（如本 Goal 涉及）；
- 不允许 TODO、空实现、仅接口或只在测试环境生效的产品路径。

## 禁止事项

- 不改写 v1.2.2 Goal/Skill/Outcome/Recovery Authority；
- 不让 LLM 直接写权威状态；
- 不保存私有思维链；
- 不引入 Python Sidecar 或文件型知识权威；
- 不让 Candidate 绕过 Promotion；
- 不自动发布 Skill；
- 不删除失败测试或降低冻结验收标准；
- 不修改与本 Goal 无关的功能，除非为修复真实架构阻断并记录 ADR。

## 验证

- RRF 排名和结构化过滤。
- 非 Active 知识不可返回。
- 用户/租户作用域隔离。
- 同一 Session 不重复注入。
- 关系扩展受深度和数量限制。
