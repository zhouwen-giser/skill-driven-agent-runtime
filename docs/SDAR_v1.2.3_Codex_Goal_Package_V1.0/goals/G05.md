## 必须完成的实施任务

1. 实现 PLAN_REVIEW 状态机。
2. 调用基础 User Goal Planner 生成 Candidate Skill Goal DAG。
3. 实现自然语言→Structured Patch Model Stage。
4. 支持增删 Skill Goal、修改 Goal、依赖、优先级、并行、Coverage 和确认策略。
5. Patch 先经 Patch Schema/权限校验，再生成新不可变 Candidate Version。
6. 每个 Candidate 重新执行 DAG、Bounds、Coverage、Capability Shape、Policy、Side Effect、No Replay 校验。
7. 实现 Plan Diff 和 Experience Hint 展示字段。
8. 仅 Confirmed Candidate 可交接给 v1.2.2；交接使用 `goalId+goalVersion` 锁。
9. 实现 manual_all、manual_risky、auto_validated、never_auto 策略，但高风险始终人工。

## 实施细则

- 先审计当前仓库符号和测试，禁止创建重复服务或第二权威；
- 所有新 Domain 对象必须有 factory/validator、immutable snapshot 和明确 error code；
- 所有模型输出必须使用 Zod/JSON Schema，并由确定性 Application 代码校验；
- PostgreSQL 写入必须定义事务、CAS/幂等和重启语义；
- Redis/BullMQ 数据必须可由 PostgreSQL 重建；
- 适合时先加入失败测试，再完成实现；
- 更新 OpenAPI、Acceptance Map、Architecture、Migration 和 Console（如本 Goal 涉及）；
- 不允许 TODO、空实现、仅接口或只在测试环境生效的产品路径。

## 禁止事项

- 不改写 v1.2.2 Goal/Skill/Outcome/Recovery Authority；
- 不让 LLM 直接写权威状态；
- 不保存私有思维链；
- 不引入 Python Sidecar 或文件型知识权威；
- 不让 Candidate 绕过 Promotion；
- 不自动发布 Skill；
- 不删除失败测试或降低冻结验收标准；
- 不修改与本 Goal 无关的功能，除非为修复真实架构阻断并记录 ADR。
