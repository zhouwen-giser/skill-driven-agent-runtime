## 必须完成的实施任务

1. 实现 Capability、Understanding、Goal Session、Planning Session、Experience、Knowledge API。
2. 所有写 API 要求 auth、actor、reason、expectedVersion、idempotencyKey。
3. 实现 Task Understanding、Goal Contract Review、Plan DAG Review 页面。
4. 实现 Experience Governance、Capability Cognition、Task Type Governance 页面。
5. 实现 Candidate Promote/Reject/Revalidate/Deprecate 和 Dead Letter Replay。
6. 实现 A2A input-required 的回答/确认路由。
7. 更新 OpenAPI、Console Route、错误展示和审计详情。
8. Console 不允许直接修改 Provider/Outcome/Active Plan。

## 实施细则

- 先审计当前仓库符号和测试，禁止创建重复服务或第二权威；
- 所有新 Domain 对象必须有 factory/validator、immutable snapshot 和明确 error code；
- 所有模型输出必须使用 Zod/JSON Schema，并由确定性 Application 代码校验；
- PostgreSQL 写入必须定义事务、CAS/幂等和重启语义；
- Redis/BullMQ 数据必须可由 PostgreSQL 重建；
- 适合时先加入失败测试，再完成实现；
- 更新 OpenAPI、Acceptance Map、Architecture、Migration 和 Console（如本 Goal 涉及）；
- 不允许 TODO、空实现、仅接口或只在测试环境生效的产品路径。

## 禁止事项

- 不改写 v1.2.2 Goal/Skill/Outcome/Recovery Authority；
- 不让 LLM 直接写权威状态；
- 不保存私有思维链；
- 不引入 Python Sidecar 或文件型知识权威；
- 不让 Candidate 绕过 Promotion；
- 不自动发布 Skill；
- 不删除失败测试或降低冻结验收标准；
- 不修改与本 Goal 无关的功能，除非为修复真实架构阻断并记录 ADR。
