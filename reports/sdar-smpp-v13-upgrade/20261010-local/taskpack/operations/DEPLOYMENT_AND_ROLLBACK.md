# 现场授权、升级与回滚手册

本手册是后续执行规格，不代表已得到现场控制或部署授权。填写模板不是授权本身，必须有用户实际批准的目标、操作范围与有效期记录。

## 1. 权限分层

| 权限 | 默认 | 允许行为 |
|---|---|---|
| 文档/任务包生成 | 本次已授权 | 创建本任务包及本地包级校验 |
| 本地代码实现 | 用户明确将 Codex 指向本包后 | 目标 SDAR 工作树内实现、隔离依赖与测试 |
| 远端 push / PR | 不自动授权 | 仅按用户具体指令发布；不覆盖 PR34 审查结论 |
| 合并 | 不自动授权 | 依用户指令和仓库保护规则，不跳过检查 |
| 现场只读 | 独立授权 | 已指定端点和原任务的只读合同/业务验证 |
| 现场业务变更 | 独立授权 | 有限的非武器导航或观察答复；不包含新增独立锁定 |
| 部署/迁移 | 独立授权 | 指定镜像、存储迁移、回滚窗口和服务范围 |
| 设备直连、发射 | 禁止 | 无许可升级路径 |

历史“可以连接 MQTT/MCP”的许可不能被扩大到重启、迁移、创建车辆任务或任何禁用功能。本轮无独立 SDK，不要让所谓验证脚本绕过 Runtime 访问设备。

## 2. 升级前只读清单

记录实际 SDAR/SMPP image digest、应用 SHA、协议/manifestHash、身份/mode、活动 Task、冻结 authority、pending/uncertain 控制、订阅 generation/水位、已选 GOWM 角色和迁移状态。只保存脱敏值，不打印 Token、连接密码或密钥。

若实际 SMPP 非兼容 SHA：停止现场写入，比较合同与实现差异；离线开发可以继续。不能仅因为版本号都叫 v1.3 就宣称兼容。

核对 `UGV_FIRE_ENABLED=false`、用户显式 NO 与原安全策略；不改变它们来完成验收。health/readiness 通过不是派发控制许可。

## 3. 本地验收先行

只有 AC-001–044、047–050 中适用于当前环境的代码/合同/PG/E2E 场景和仓库所需门禁状态清楚，才讨论现场写验证。selected GOWM 的资格单列，普通 PG 通过不能替代。阻塞应附原始错误和最小外部依赖，不通过直写业务表临时绕过。

## 4. 部署切换

优先在原路径安全排空活动业务任务后切换；活动任务无法排空时，需要证明新版本可以仅凭原 binding/command journal 恢复，且只有一个有效发送者。不能把两套不同版本同时接到同一真实任务上共同写入。

数据库增量迁移必须由当前正式 owner 机制执行。保存备份/恢复点和角色权限说明，禁止删除业务历史以获得“干净现场”。部署仅切 SDAR 被授权服务，不改 SMPP/设备/周边基础设施。

启动后先执行只读验证，观察日志/metrics、旧任务读取、订阅恢复和零额外变更。任何自动新建 Task 或重复 control 属于立即停止写入的事件。

## 5. 授权业务验收与停止条件

用户确认明确的任务/设备、允许操作、次数或预算、时间窗口及停止方式后，才执行有限场景。始终经正式 Task/Skill/控制入口；不要用直接 adapter 调用掩盖上层未接线。

立即停止新的业务变更并保存事实的条件：身份不一致、未知 authority、合同漂移、重复发送迹象、请求已被替换、无法确认取消状态、通信异常导致命令不确定、禁用策略改变。停止新发送不等于声称物理设备已经停止；需要按原授权取消/停机流程观察确认。

受理、应用、完成分别记录。Task natural completion 与取消竞争时保留真实终态，不强改成“取消成功”。现场失败数据保留，不通过重启、删任务或重试到成功来掩盖。

## 6. 回滚预检

检查新版本是否存在旧版无法理解的 prepared/dispatching/accepted/uncertain 命令、新对象格式或迁移变化。存在未决命令时，旧版不能接管写入；可保持只读排障、先完成原命令核对，或在明确方案下保留新版本管理这一任务。

代码回滚不等于数据库回滚。优先保留向后兼容增量结构，不删除新证据/命令记录。只有证明无旧写入者、新数据有保存方案且 rollback migration 已通过真实测试时，才执行对应逆向迁移。

## 7. 最终交付

单列本地开发、受管读/写、隔离 E2E、selected GOWM、site read、site business 与 deployment 状态。未授权的 site 项为 NOT_RUN。若没有做现场业务调用，则明确写“未新建真实设备任务、未执行现场业务控制”，不从历史部署记录推断本轮通过。
