1. 引言
1.1 编制目的
本说明书用于定义一个可复用的通用 Agent Server 模板。该 Server 对外以 A2A 1.0.0 协议提供标准 Agent 服务，对内管理远程 MCP 工具与 Skill，并由 LLM 依据用户目标选择和组合 Skill、生成结构化动态 Workflow、编译为 LangGraph.js 执行，最终通过目标达成评估形成闭环。
本说明书是产品设计、领域建模、接口设计、开发拆分、测试用例编制和首版验收的统一依据。
1.2 建设目标
提供一个不包含具体行业知识的纯通用 Agent Runtime，所有业务能力均通过 Skill 与 MCP Tool 注入。
使任意兼容 A2A 1.0.0 的客户端能够提交任务、确认计划、补充输入、暂停、恢复、取消和获取结果。
以自然语言 Skill 为主要能力表达，由 LLM 在注册时补全输入/输出 JSON Schema，并约束可用 MCP 工具范围。
由 LLM 生成结构化 Workflow DSL，经严格校验后编译为 LangGraph.js 执行，而不是动态运行模型生成的 TypeScript 代码。
通过“执行—结果处理—目标评估—外层重规划”持续推进用户目标，直至达成、等待输入、取消、失败或预算耗尽。
以执行经验、长期记忆、多评估器和隐式用户反馈驱动 Skill、Workflow Template 与 Prompt 的持续演化。
1.3 设计原则
原则
说明
协议标准优先
A2A 层严格使用标准任务状态和官方 SDK，不修改协议状态枚举；内部细粒度阶段通过状态消息表达。
能力即 Skill
Agent 本身不内置行业业务逻辑，能力通过可版本化 Skill、MCP Tool 和模型配置注入。
LLM 决策优先
意图、目标、Skill 选择、Workflow 规划、工具异常决策和目标评估均由 LLM 完成；检索与结构化数据只提供上下文和约束。
规划与执行分离
默认先生成并确认计划，再编译执行；Skill 可配置自动确认，但 Goal 变更后的新计划必须重新确认。
单轮图稳定、外层闭环
单次 Workflow 执行期间图结构不变，运行结束或失败后由外层控制器重新规划。
可观察与可演化
完整保存任务、模型、MCP、Workflow、评估和版本记录，支持回放、分析和自动演化。
首版可信内网
首版不实现认证和权限模型，依赖可信内网部署，但密钥必须加密存储。

1.4 术语与缩略语
术语
定义
A2A
Agent2Agent 协议。首版锁定 1.0.1，Agent Server 仅作为 Provider，不主动调用其他 A2A Agent。
MCP
Model Context Protocol。首版仅支持远程 MCP Server 的 Tools，使用统一传输适配层，首个适配器为 Streamable HTTP。
Skill
描述 Agent 能解决什么目标、允许/需要/禁止哪些工具、建议流程、输出要求及运行策略的版本化能力包。
Workflow DSL
LLM 生成的结构化 JSON 工作流定义，经 Schema 和图结构校验后编译为 LangGraph.js。
Goal
在一个 context_id 中持续推进的活动目标，可被后续消息补充、修改、取消或形成后续阶段。
Workflow Template
由高频、稳定、成功的动态 Workflow 沉淀出的可复用模板，后续仍可按上下文调整。
长期记忆
由任务轨迹提炼出的事实、成功经验、失败经验、优化经验等可检索信息，使用 pgvector 支持语义检索。
任务质量报告
由目标、Workflow、Skill、结果和工具调用等多个评估器交叉评价后形成的结构化报告。

2. 产品范围与边界
2.1 产品定位
系统定位为单 Agent、单机、单进程部署的通用 Agent Server 模板。它不是多 Agent 编排平台，也不是行业应用本身；其价值在于提供标准化 A2A 接入、MCP Tool 管理、Skill 生命周期、动态 Workflow 生成执行、目标闭环、长期记忆和能力演化的统一运行时。
2.2 首版范围
A2A 1.0.0 Provider 服务、Agent Card、非流式请求、标准流式事件和任务轮询。
多用户共享能力库；user_id 可选，缺省为 anonymous；context_id 缺省时自动创建。
会话级单活动 Goal、多轮 Goal Patch、Goal 关系判断、计划确认与重新审议。
远程 MCP Server 运行时注册、工具发现、固定凭据管理、工具元数据增强和手动刷新。
Skill 创建、注册、Schema 生成、发布、版本、回滚、禁用、图谱、组合、评估与自动演化。
Workflow DSL 生成、校验、自动修复、可视化编辑、LangGraph.js 编译和执行。
同步/异步混合任务、Redis 持久化排队、暂停、恢复、取消、等待输入、等待确认。
智能结果处理、结构化结果、目标达成评估、外层重规划和替代 Skill 计划。
PostgreSQL + pgvector 数据层、Redis 运行态与 BullMQ 队列。
完整运营管理控制台，包括执行回放、评估分析、记忆管理、版本对比和优化建议。
2.3 主要使用者
参与者
职责
A2A 客户端
提交或延续任务、确认或修改计划、补充输入、暂停/恢复/取消任务、获取状态和结果。
Agent Server
理解目标、选择 Skill、生成计划、执行工具、评估目标、管理任务状态和沉淀经验。
系统管理员
通过管理控制台注册 MCP、维护 Skill/Prompt、确认计划、查看轨迹、修正草案和管理记忆。
远程 MCP Server
提供可发现和可调用的工具。首版不提供 Resources 与 Prompts。
LLM Provider
为不同阶段提供固定配置的模型服务。

2.4 首版边界假设
部署在可信内网，A2A 接口、管理 API 和控制台均不认证。
系统同时处理约 1～10 个任务，且同一 context_id 内严格串行。
Agent Server、A2A/API、队列 Worker 和 LangGraph 执行均在一个 Node.js 进程内运行。
执行中任务在进程崩溃或 Redis 数据丢失后不恢复、不自动重试；排队但未执行的任务可由 BullMQ 保留。
MCP 工具若存在副作用，应由工具本身尽量保证幂等；首版运行时不提供幂等键、去重或逐次副作用确认。

4. 核心业务流程
4.1 A2A 任务主流程

图 2  A2A 任务、计划确认与目标闭环流程
任务主流程必须遵循以下顺序：
解析 A2A 消息中的可选 user_id 与 context_id；user_id 缺省为 anonymous，context_id 缺省时自动创建。
加载会话历史、全局长期记忆和当前活动 Goal，判断新消息是新目标、目标补充、Goal Patch、计划确认、补充输入还是控制命令。
由 LLM 识别意图与目标，并选择一个或多个 Skill；若存在 MCP Tool 但缺少 Skill，生成仅限当前任务的临时 Skill；若缺少必要工具，进入能力缺口等待。
基于 Skill、工具定义和阶段记忆生成 Workflow DSL，经校验和自动修正后编译为 LangGraph.js。
默认进入计划确认；Skill 可配置自动确认。A2A 客户端可自然语言修改，管理端可编辑 DSL/DAG。
执行 Workflow，工具失败时由 LLM 动态决定重试、调整参数、替代工具、调用其他 Skill 或终止。
智能结果处理层生成符合 Skill output_schema 的结构化数据及自然语言结果。
多评估器判断目标是否达成；未达成且仍可继续时进入外层重规划，并产生新计划。
任务结束后归档完整轨迹，提炼长期记忆，更新指标，并触发 Skill/Workflow/Prompt 演化判断。
4.2 Goal 变更与重新审议
强制规则：任何 Goal Patch 一旦生效，当前 Workflow、已完成步骤和中间结果全部作废；原计划确认失效，新计划必须重新确认，即使新 Skill 配置了自动确认。

Agent 先生成结构化 Goal Patch，识别新增、修改、删除的目标、约束和成功标准。
旧 Workflow 状态及结果标记为 invalidated，不参与新计划的数据复用。
已经产生的外部副作用不会自动消失；按原 Skill 的 compensation_policy 生成补偿步骤，未定义补偿时保留副作用并告警。
重新执行 Skill 选择、Workflow 生成、计划确认和目标闭环。
4.3 Skill 自动沉淀与演化

图 3  Skill 自动沉淀、验证、发布与人工修正流程
自动演化只在满足最低相似成功次数后触发。LLM 需进一步判断通用性、稳定性、重复度及与已有 Skill 的关系；能力边界一致时创建现有 Skill 新版本，边界显著不同则创建新 Skill。自动发布前必须完成静态校验、历史回放和 LLM 补充测试，且全部用例通过。

6.1 核心实体
实体
职责/关键数据

ConversationContext
由 context_id 标识，维护消息历史、活动 Goal 和串行任务队列。

目标、约束、成功标准、状态、父/后续阶段关系和 Goal Patch 历史。
A2ATask
协议任务标识、标准状态、内部阶段、等待原因、同步/异步模式和结果引用。
Skill
稳定标识、名称、状态、当前版本和全局统计。
SkillVersion
自然语言描述、input/output Schema、工具边界、运行策略、来源、版本和验证状态。
SkillRelation
依赖、父子、替代、组合、输入输出匹配等图谱关系。
McpServer
远程地址、传输适配器、加密凭据、状态和注册时间。
McpTool
原始名称、描述、input Schema、增强元数据、所属 Server 和刷新信息。
WorkflowPlan
计划说明、DSL、版本、确认状态、来源 Skill、预算和校验结果。
WorkflowInstance
编译图引用、运行状态、节点状态、Checkpoint 引用和重规划轮次。
WorkflowNodeExecution
节点输入、输出、状态、开始结束时间、错误和重试/异常决策。
McpInvocation
工具、参数、结果、错误、耗时和是否可能产生副作用。
ModelInvocation
阶段、Provider、模型、Prompt 版本、请求/响应、Token 和耗时。
ExecutionArtifact
结构化结果、自然语言结果、事实提取和输出 Schema 校验信息。
MemoryRecord
类型、内容、向量、状态、来源任务、替代关系、可信度和适用阶段。
ExperienceRecord
成功/失败经验、目标模式、工具组合、Workflow 特征和评估。
EvaluationReport
多评估器评分、结论、证据、改进建议和隐式反馈。
PromptTemplateVersion
阶段 Prompt 内容、版本、状态、来源、评估和发布信息。
ValidationSuite
Skill 测试用例、Mock 工具结果、期望输出和验证记录。

BullMQ 任务队列、活动任务运行态、LangGraph Checkpoint、短期上下文、缓存、事件和会话串行锁。
主密钥
由部署环境提供，用于解密 PostgreSQL 中的 MCP 和模型凭据；主密钥本身不得存入数据库。

7. 接口需求
7.1 A2A 接口约束
使用 A2A 1.0.0 官方 TypeScript SDK 提供的标准接口与对象。
Agent Card 能力列表由启用 Skill 动态生成。
user_id 作为可选 metadata；context_id 未提供时由服务创建。
内部阶段不扩展协议状态，只通过标准状态消息说明。
计划确认、补充输入和计划修改通过后续 A2A 消息完成。
最终返回文本 Part 与结构化数据 Part；首版不要求文件 Artifact 或多模态内容。
流式连接断开不影响任务，客户端可重连或使用非流式状态查询。

9.2 Skill 选择与工具边界
规划前，系统可通过标签、图谱、元数据和向量召回候选 Skill；最终选择由 LLM 完成。
required_tools 缺失时，Skill 不具备完整执行条件；系统应返回能力缺口或选择替代 Skill。
optional_tools 允许 Agent 根据上下文取舍。
forbidden_tools 是硬约束，DSL 校验器必须拒绝包含禁止工具的计划。
Skill 描述可以定义推荐步骤，但 Agent 以目标驱动方式自主生成 Workflow。

10.2 节点类型
节点类型
语义

10.3 校验规则
JSON 必须满足 Workflow DSL Schema，所有必填字段存在且类型正确。
节点 ID 全局唯一，entry_node 必须存在，所有边的 source/target 必须存在。
至少存在一个可达终止节点；不得存在无出口且未声明终止的死节点。
循环必须声明最大迭代次数或可证明受预算约束。
并行分支必须声明汇聚节点和冲突合并策略。
mcp_tool 节点引用的 Server/Tool 必须存在，参数映射必须与当前 Tool Schema 兼容。
skill_call 节点引用的 Skill 必须启用，且规划时记录的能力边界不得违反当前版本。
不得包含主 Skill forbidden_tools。
所有输出必须可映射到 Workflow/Skill output_schema。

13. 验收要求
13.1 完成定义
首版完成标准：本次需求澄清中确定的全部能力均属于首版验收范围，不以“最小闭环”代替完整需求。

13.2 端到端验收场景
场景
验收内容
AC-01 基础任务闭环
A2A 客户端提交目标；Agent 选择 Skill、生成计划、确认、调用 MCP、评估目标并返回文本与结构化结果。
AC-02 自动确认
启用 auto_confirm_plan 的 Skill 生成合法计划后可直接执行；Goal 变更后仍必须重新确认。
AC-03 计划修改
A2A 客户端自然语言修改计划；管理端编辑 DAG/DSL；重新校验后执行。
AC-04 多轮 Goal
同一 context_id 中补充目标、修改约束、完成旧 Goal 后创建相关后续阶段或新 Goal。
AC-05 Goal Patch 失效
部分执行后修改 Goal；旧 Workflow 和结果全部 invalidated，副作用按补偿策略处理，新计划重新确认。
AC-06 Skill 组合
主 Workflow 通过 skill_call 调用子 Skill，使用执行时当前版本，并分别记录状态与评估。
AC-07 能力缺口
无必要 MCP Tool 时进入 input-required/等待能力状态并返回清晰缺口；有 Tool 无 Skill 时生成临时 Skill。
AC-08 外层重规划
首轮 Workflow 未达成 Goal，系统生成下一版计划并继续闭环；达到预算后终止。
AC-09 工具异常
MCP 调用失败，LLM 根据错误选择改参、重试、替代工具或终止，并保存决策记录。
AC-10 暂停恢复取消
验证尝试中断、节点边界暂停、短暂停恢复、长暂停重新规划、取消默认策略和等待超时取消。
AC-11 队列与故障
同 context 串行；待执行任务重启后保留；执行中任务崩溃后失败且不重试。
AC-12 Skill 注册
自然语言描述经 LLM 生成 input/output Schema；不合法时注册失败。
AC-13 Skill 自动演化
相似成功经验达到阈值，归纳候选 Skill，完成回放和补充测试，全部通过后自动发布。
AC-14 人工修正
验证失败草案由管理员修正后重试，修正记录进入演化经验。
AC-15 Prompt 演化
系统生成候选 Prompt 版本，未发布前不生效；管理员发布后新调用关联新版本。
AC-16 记忆与检索
完整轨迹归档，提炼记忆可按阶段检索；记忆支持 superseded/invalid。
AC-17 管理控制台
完成 MCP、Skill、Prompt、任务、Workflow、记忆、评估、回放和运营分析全流程。
AC-18 A2A 流式
标准事件流可展示状态更新；连接断开后任务继续，轮询可获得最终结果。

13.3 测试覆盖要求
所有 FR 和 NFR 必须至少对应一个自动化或可重复执行的验收用例。
Workflow DSL 每种节点类型必须具备正常、边界和异常测试。
A2A 协议对象和状态映射必须执行契约测试。
Skill 自动发布必须验证“全部用例通过”的门禁。
必须覆盖进程崩溃、Redis 重启、模型故障、MCP 超时、流式断连和等待超时。
必须验证无认证环境、anonymous 共享历史和全局记忆带来的行为符合需求。
14. 明确接受的风险与约束
风险
影响
当前缓解措施
R-01 无认证与权限
任意内网调用方可访问 A2A、管理 API、Skill、记忆和密钥管理操作。
严格网络隔离；后续版本增加认证中间件。
R-02 anonymous 共享历史
未传 user_id 的不同客户端共享 anonymous 历史，可能相互污染上下文。
建议正式使用时显式传 user_id。
R-03 长期记忆全局共享
用户事实和任务经验可被其他用户检索，存在数据隔离和隐私风险。
首版按已确认需求实现；后续增加记忆作用域。
R-04 无副作用幂等保护
重试、重规划或客户端重提可能重复创建、发送或修改。
优先接入幂等 MCP Tool；Skill 明确风险和补偿。
R-05 执行中任务不恢复
进程或 Redis 故障导致任务失败和进度丢失。
客户端重提；后续引入关键 Checkpoint 持久化。
R-06 无模型降级
任一阶段模型不可用会直接导致任务失败。
监控模型可用性；后续增加备用模型。
R-07 Tool 定义不锁版本
手动刷新后 Skill 可能在未更新情况下使用新 Schema。
依赖告警；管理员及时维护。
R-08 依赖破坏只告警
工具删除或 Schema 变化后 Skill 仍启用，实际任务可能失败。
控制台突出告警；人工处理。
R-09 低质量 Skill 不自动下线
已知低质量 Skill 仍可被选择。
LLM 参考历史指标；管理员禁用。
R-10 首版范围过大
完整运营控制台、演化、回放和协议能力同时纳入首版，开发量和集成风险高。
按实施顺序分阶段集成，但最终验收不缩减。
R-11 单进程资源竞争
API、模型编排、队列和执行共享进程，阻塞或内存压力影响全部能力。
限制 1～10 并发，避免 CPU 密集同步任务。
R-12 完整调用记录
保存 Prompt、上下文和模型响应会增加数据量和敏感信息暴露面。
可信内网、数据库访问控制和后续保留策略。
