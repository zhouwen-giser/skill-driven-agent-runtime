# SDAR v1.3 Final Architecture Inventory

Status: `AUDITED`

## Runtime shape

SDAR v1.3 remains one Node.js/TypeScript modular-monolith process. The standard
Server composes the Application services, the single LangGraph.js execution
runtime, PostgreSQL repositories, Redis/BullMQ wake workers, the A2A adapter,
the Management API and the Console projection. No P01-P12 increment introduces
a second Agent, workflow engine, formal Task state machine or business
authority.

```text
A2A / Management / Console
          |
          v
Application commands and read projections
          |
    +-----+---------------------+
    |                           |
    v                           v
Formal Goal/Plan/Task      Artifact compiler/runtime
and LangGraph runtime      P03-P11, policy guarded
    |                           |
    +------------+--------------+
                 v
          PostgreSQL authority
                 |
                 v
      transactional Outbox facts
                 |
                 v
 Redis/BullMQ wake, queue and rebuildable projections
```

## Persistent and ephemeral infrastructure

- PostgreSQL plus pgvector is the sole persistent system of record.
- The migration chain contains the preserved V1 baseline, v1.2.3 migrations
  `0108` through `0124`, and v1.3 additive migrations `0125` through `0134`.
- Redis/BullMQ queues cover serialized context work, remote MCP Task polling,
  continuation and cancellation, Experience processing, P03/P04 compilation,
  replay validation, shadow execution and revalidation.
- Every queued item is a wake or durable-reference envelope. Authoritative
  Goal, Plan, Attempt, Outcome, Candidate, validation, activation and audit
  records live in PostgreSQL.

## Public surfaces

- A2A exposes the frozen Agent Card, message/task protocol, input-required and
  resumable event semantics through the adapter.
- Management OpenAPI describes health, Goal/Task/Workflow, MCP, Skill,
  Experience, Artifact, runtime evidence, governance and SSE operations.
- Console uses those real Management endpoints and does not contain a fixture
  product path.
- Artifact management identity is resolved by the deployment adapter. Actor,
  tenant, kind and roles are not accepted from a command body.
- All protocol surfaces remain projections over formal application commands
  and PostgreSQL facts.

## Release controls

The frozen P02/P07 flags are retained and P13 adds explicit, default-off
controls for compiler, registry, shadow, promotion, retrieval, model routing
and exact versioned Artifact allowlisting. Tenant, Artifact type, fast gateway,
Case, Model cascade and mode controls remain independently switchable.
Malformed booleans and Artifact references fail closed.

## Audit conclusion

The static architecture gate and the P13 authority audit are the executable
deciders for this inventory. Any unexplained writer, cache-only formal state,
direct UI/A2A mutation, automatic Worker approval, model-created formal Plan or
non-LangGraph workflow execution is release-blocking.
