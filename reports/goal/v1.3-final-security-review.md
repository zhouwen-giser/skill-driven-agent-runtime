## Accepted

1. **Artifact Bearer identity and Standard Server composition.**
   `ConfiguredBearerArtifactManagementIdentity` hashes the exact configured
   `Bearer` header with SHA-256 and compares fixed-length digests using
   `timingSafeEqual`. Actor, optional tenant, human/service kind and the closed
   role set come only from validated environment configuration. The
   deployment-owned provider rejects actor, tenant or permission expansion.
   `main.ts` injects the principal resolver and operator identity together, and
   `runtime.ts` composes P12 management only when both ports and migration 0134
   are present. `scripts/smoke-server.mjs` exercises the real standard entry
   point and requires unauthenticated `401` plus authenticated `200`.

2. **RBAC, tenant and spoofing boundaries.** Query and command services derive
   scope and permission from the resolved principal, command JSON is strict,
   service principals cannot approve, activate, disable a kill switch or
   perform other human-only actions, and the PostgreSQL repository uses
   parameterized tenant predicates. Cross-tenant detail/view/runtime requests
   are concealed as `404`; sensitive management values are recursively
   redacted and reads are audited. Tenant omission is documented as an
   explicitly global deployment operator choice, not a request-controlled
   privilege.

3. **Fail-closed release controls.** All additive Artifact flags default to
   false, malformed boolean or versioned-ref values throw before infrastructure
   opens, compiled paths require their complete flag conjunction, and an empty
   exact `artifactId:version` allowlist denies all compiled retrieval. The
   tenant allowlist retains the frozen P07 semantics while authorization,
   tenant matching, policy, capability and kill-switch checks remain mandatory.

4. **Supply-chain identity.** The locked production audit records zero Critical
   and zero High findings. The prior High `fast-uri@3.1.3` finding is closed by
   the exact workspace override to `3.1.4`; the lockfile, source intake,
   ADR-123, 34-entry source lock, BSD-3-Clause notice, SBOM and license report
   agree. One Moderate `@hono/node-server` `serve-static` advisory remains a
   documented watch item; that export is not imported by the composed runtime.
   The exact Trivy reports bind PostgreSQL/pgvector to
   `sha256:856ba6c2ed2292bba994e945ebf1bd638d2c1c78c2562bc9c8b57ea6b9138762`
   and Redis to
   `sha256:8096655e437712b07503796fb64d81359256cfcff0ab29d95a7da72863786efb`,
   each with zero Critical/High findings. The SBOM contains 298 components,
   including `fast-uri@3.1.4`; the 286-package license inventory has zero
   unknown licenses.

5. **Privacy, deletion and limitations.** Existing unit and real PostgreSQL
   tests cover recursive credential/private-reasoning/PII redaction,
   tenant-scoped management access, user-scope deletion of compiled Experience
   traces/patterns/runs, projection deletion and idempotent propagation. The
   known-limitations record truthfully preserves the trusted-intranet boundary,
   deployment-owned credential rotation/revocation, organization retention and
   deletion responsibilities, synthetic non-PII test scope, point-in-time scan
   limits and the prohibition on interpreting local evidence as production
   Internet hardening.
