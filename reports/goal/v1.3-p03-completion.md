## Ordering / Concurrency / Branch Policy

Stable event time, source ordinal and identity determine replay order. Equal timestamps never imply
parallel execution. Parallel candidates require explicit concurrency/parent/dependency evidence.
Branch, correction, failure, recovery trigger and resume evidence remain explicit.

## Redaction / Classification

Credential/authorization material, private reasoning, unnecessary PII and oversized raw payloads
are rejected or reduced to bounded structural summaries before persistence. Missing facts remain
explicit codes and reduce completeness; the normalizer does not fabricate replacement events.

## Fingerprints

Canonical JSON plus SHA-256 binds Episode source, Trace, goal, capability and environment inputs.
Trace identity is deterministic under source hash and normalizer version. The compatibility request
fingerprint is a cohort key only and retains `task_type_missing`.

## Persistence / Worker

- Canonical Trace authority: `experience_trace`
- Canonical Pattern authority: `pattern_candidate`
- Complete support evidence: `pattern_candidate_support`
- Durable compiler delivery/lease authority: `compilation_run`
- Queues: `sdar-compiler-normalization`, `sdar-compiler-process-mining`

PostgreSQL owns idempotency, retry/dead-letter, lease fencing and source-event lineage. Redis stores
run-ID wakes only. Server startup/runtime composes source dispatch, two reconcilers and two bounded
workers. A terminal expired lease at `attempt == maxAttempts` is moved to dead letter.

## G06 Cohort

Cohorts require exact tenant, Task Type compatibility key and minimum completeness, with optional
goal/capability/environment/device/time filters. Contract version, algorithm version, canonical
cohort and mandatory threshold bind the cohort fingerprint.

## Variant / Direct-Follows / Precedence

Variants preserve exact activity, explicit concurrency and branch sequence, including loops.
Direct-follows uses adjacent distinct activities. Precedence requires the predecessor's last
occurrence before the successor's first occurrence.

## Mandatory / Optional / Parallel / Recovery

Mandatory/optional classification uses the persisted auditable threshold. Parallelism requires
explicit evidence. Recovery retains trigger, resume activity and suffix sequence. Failure variants
remain separate and reverse-order evidence is retained as contradiction.
