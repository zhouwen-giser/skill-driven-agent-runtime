## Error budget contract

The named operations owner must approve:

- rolling window and excluded maintenance periods;
- SLO target for each applicable SLI;
- allowed bad-event count or duration;
- fast-burn and slow-burn multipliers and evaluation windows;
- deduplication and late-data policy;
- change-freeze and rollback/disable conditions.

Proposed calculation:

```text
error_budget = eligible_events * (1 - approved_slo)
consumed_budget = authoritative_bad_events
remaining_budget = error_budget - consumed_budget
```

## Manual response policy

Excessive burn recommends, but does not automatically perform:

1. pause rollout expansion;
2. pause new Artifact activation;
3. retain Cognitive Fallback;
4. disable the affected fast/model path through an authorized operator;
5. open an incident and independent review.
