# SDAR v1.3 Rollback and Kill Switch Runbook

Status: `PLAN_ONLY_NOT_EXECUTED`

## Preconditions

Required before any command:

- approved release and deployment manifest;
- incident/change identifier;
- named operations and rollback owners;
- exact environment, tenant and Artifact scope;
- frozen pre-change configuration and active-pointer snapshot;
- monitoring access and communication channel;
- explicit human approval for the selected operation.

None of these production preconditions is currently available.

## Global fast-path stop

Planned order for an authorized deployment:

1. set `SDAR_V13_FAST_GATEWAY_ENABLED=false`;
2. set `SDAR_V13_MODEL_ROUTE_ENABLED=false` and
   `SDAR_V13_MODEL_CASCADE_ENABLED=false` if relevant;
3. remove the affected exact `artifactId:version` from
   `SDAR_V13_ARTIFACT_ALLOWLIST`;
4. disable the affected Artifact type path;
5. set `SDAR_V13_RETRIEVAL_ENABLED=false`;
6. if isolation is uncertain, set `SDAR_V13_ARTIFACT_MODE=off`;
7. restart only through the deployment platform's approved change procedure;
8. verify Cognitive Fallback and formal Task continuity.

The values above are a reviewed sequence, not commands executed by P14.

## Artifact active pointer

If an approved predecessor exists, the rollback owner invokes the existing P06
governance command with authenticated operator identity, exact target Artifact,
expected pointer lock version, validation-summary hash, reason and idempotency
key. Verify the single PostgreSQL pointer, audit record and Outbox event before
reopening retrieval. Never update the pointer table directly.

## Kill Switch

- Enable: use the authenticated security-operator control for the approved
  scope and verify the durable governance fact.
- Disable: allowed only through evidence-bound rollback to an approved target.
- An alert may recommend these actions but cannot perform them.

## Provider and Model Route

Disable only the affected Provider/Model path after confirming Cognitive
Fallback capacity, residency/classification policy and dependent profiles.
Do not delete the Provider profile or credential record.

## Application rollback

Redeploy only an immutable previously approved build whose schema compatibility
with the current migration ledger is proven. Preserve new PostgreSQL facts.
Data-bearing migrations prefer a reviewed forward fix; no unreviewed
production down migration is permitted.

## Verification checklist

- formal Goal/Plan/Attempt/Outcome chain unchanged;
- no provider operation replayed;
- affected compiled path no longer selected;
- Cognitive Fallback available;
- pointer, definition, audit and Outbox facts agree;
- Redis projection rebuild matches PostgreSQL;
- duplicate wakes/events remain idempotent;
- Management API, SSE and A2A expose the authoritative state;
- actor, approval, reason and request identity are recorded.
