## Accepted

- **P13-AR-MAJ-001 remains closed.** The promotion-controlled set contains
  `build-promotion-package`, `approve`, `reject`, and `activate`. The standard
  Server injects the release policy into `ArtifactManagementCommandService`,
  and the service evaluates it before any promotion package or governance
  write. Promotion-package composition is also absent while promotion is
  disabled.
- **P13-AR-MAJ-002 is closed.** `policyOperationFor` evaluates the effective
  semantics before the governance dispatch:
  `validate + validationType=shadow` maps to `shadow`, while
  `validate + validationType=revalidation` maps to `revalidate`. Both therefore
  use the shadow-controlled deny path when
  `SDAR_V13_SHADOW_ENABLED=false`. Ordinary `static`, `replay`, and
  `simulation` validation remains available as intended.
- **The alias rejection is proven before authority writes.** The focused unit
  test submits both aliases and proves `requestValidation` is never called. The
  real Bearer E2E submits both aliases through the Server endpoint, requires
  `503 ARTIFACT_OPERATION_DISABLED`, and then proves zero rows in
  `artifact_validation_run` and zero `artifact.validation_started` records in
  `cognitive_runtime_outbox`.
- **The Bearer path is substantive.** The E2E uses
  `ConfiguredBearerArtifactManagementIdentity`, seeds a real P02 candidate, and
  also proves disabled promotion produces no Approval row. With promotion
  explicitly enabled it performs real static validation, persists the
  validation result, approves, activates, and verifies the PostgreSQL Active
  Pointer.
- **Emergency controls remain available.** `deprecate`, `rollback`,
  `kill-switch-enable`, and `kill-switch-disable` remain outside the
  promotion/shadow deny sets. The focused unit test proves
  `kill-switch-disable` still reaches the evidence-bound rollback port while
  promotion is disabled.
- **Authority and runtime boundaries remain intact.** Feature-policy checks
  only prevent disabled requests; they do not approve, activate, or rewrite an
  Artifact. Accepted governance state, validation runs, Active Pointers, and
  Outbox facts remain PostgreSQL-owned. Redis/BullMQ remains wake-only, and no
  second workflow runtime or Server composition root was introduced.
