# EP-11 — SDAR v1.2.1 Frozen MCP Tasks Protocol Upgrade

Status: ACTIVE — Phase 2 contracts complete; Phase 0 full infrastructure baseline pending
Branch: `feature/v1.2.1-frozen-mcp-tasks-protocol`
Baseline: `922f4288880e0fe3dee6ce402aa9788f4caa80eb`
Target version: `1.2.1`

## Purpose / Outcome

Upgrade the existing v1.2 Runtime from the isolated Legacy v1.1 MCP Tasks boundary to an explicit
dual-protocol boundary. Legacy Providers and historical plans remain readable and observable. Frozen
V1 Providers use the pinned MCP `2026-07-28` stateless contract, SEP-2663 Tasks, Task Notification,
runtime revisions, Evidence A and the SDAR task-execution profile without Bridge aliases or fallback.

## Requirements Covered

- Frozen contract sections 1–26 and all 74 conformance scenarios.
- Upgrade plan Phases 0–12 and Gates G0–G5.
- Exact source commit `26897cc322f356487da89113451bd16b520b9288`, schema blob
  `cc44564e33305dbc07e820cdd0a97648f3852019` and protocol version `2026-07-28`.
- Legacy compatibility, immutable Workflow/LangGraph authority, PostgreSQL authority and no duplicate
  Tool side effect.

## Context and Orientation

`packages/mcp-adapter` owns all official MCP wire and SDK interaction. Domain/application types remain
protocol-neutral. PostgreSQL owns Provider discovery snapshots, plan contract snapshots, bindings,
observations and controls. BullMQ/Redis may only carry reconstructable delivery references. LangGraph.js
remains the only Workflow runtime; remote completion resumes the existing immutable node through the
persisted continuation frontier.

The v1.2 business implementation and reports are complete and are not reopened. New evidence is stored
under `reports/v1.2.1-frozen-mcp-tasks/`.

## Architecture and Interfaces

- `McpTransportRouter` selects explicit `legacy_v11` or `frozen_v1`; there is no automatic translation
  or downgrade.
- `LegacyV11McpClient` retains the current SDK/Bridge path. `FrozenV1McpClient` uses stateless POST,
  per-request metadata, frozen routing headers and frozen schemas without initialize/connect.
- Domain owns protocol-mode, task-behavior, contract-snapshot, frozen observation and Provider Evidence
  models. No SDK type crosses the adapter.
- Migration 0107 adds append-only protocol discovery authority and additive frozen fields while retaining
  Legacy columns and fail-closed rollback.
- Poll, notification and reconciliation enter one observation admission service and deduplicate Frozen
  facts by `taskId + runtimeRevision`.
- Provider Evidence contains objective `evidenceType`; local Skill requirements bind by type only after
  pointer/URI/hash validation.

## Idempotence and Recovery

Protocol generation verifies pinned hashes before replacing generated files. Migration 0107 supports empty,
0106 upgrade, idempotent reapply and fail-closed rollback. Frozen registration/refresh is transactional and
cannot silently change protocol mode. Re-running observation admission is idempotent by its protocol-specific
dedupe key. No force push, history rewrite, automatic PR merge or operator-container mutation is allowed.
