# EP-11 — SDAR v1.2.1 Frozen MCP Tasks Protocol Upgrade

Status: ACTIVE — Phases 0–10 and the local Phase 12 gate complete; Phase 11 external interop blocked
Branch: `feature/v1.2.1-frozen-mcp-tasks-protocol`
Baseline: `922f4288880e0fe3dee6ce402aa9788f4caa80eb`
Target version: `1.2.1`

## Purpose / Outcome

Upgrade the existing v1.2 Runtime from the isolated Legacy v1.1 MCP Tasks boundary to an explicit
dual-protocol boundary. Legacy Providers and historical plans remain readable and observable. Frozen
V1 Providers use the pinned MCP `2026-07-28` stateless contract, SEP-2663 Tasks, Task Notification,
runtime revisions, Evidence A and the SDAR task-execution profile without Bridge aliases or fallback.

## Requirements Covered

- Frozen contract sections 1–26 and all 74 conformance scenarios.
- Upgrade plan Phases 0–12 and Gates G0–G5.
- Exact source commit `26897cc322f356487da89113451bd16b520b9288`, schema blob
  `cc44564e33305dbc07e820cdd0a97648f3852019` and protocol version `2026-07-28`.
- Legacy compatibility, immutable Workflow/LangGraph authority, PostgreSQL authority and no duplicate
  Tool side effect.

## Context and Orientation

`packages/mcp-adapter` owns all official MCP wire and SDK interaction. Domain/application types remain
protocol-neutral. PostgreSQL owns Provider discovery snapshots, plan contract snapshots, bindings,
observations and controls. BullMQ/Redis may only carry reconstructable delivery references. LangGraph.js
remains the only Workflow runtime; remote completion resumes the existing immutable node through the
persisted continuation frontier.

The v1.2 business implementation and reports are complete and are not reopened. New evidence is stored
under `reports/v1.2.1-frozen-mcp-tasks/`.

## Architecture and Interfaces

- `McpTransportRouter` selects explicit `legacy_v11` or `frozen_v1`; there is no automatic translation
  or downgrade.
- `LegacyV11McpClient` retains the current SDK/Bridge path. `FrozenV1McpClient` uses stateless POST,
  per-request metadata, frozen routing headers and frozen schemas without initialize/connect.
- Domain owns protocol-mode, task-behavior, contract-snapshot, frozen observation and Provider Evidence
  models. No SDK type crosses the adapter.
- Migration 0107 adds append-only protocol discovery authority and additive frozen fields while retaining
  Legacy columns and fail-closed rollback.
- Poll, notification and reconciliation enter one observation admission service and deduplicate Frozen
  facts by `taskId + runtimeRevision`.
- Provider Evidence contains objective `evidenceType`; local Skill requirements bind by type only after
  pointer/URI/hash validation.

## Discoveries and Surprises

- The supplied status/sync files predate PR #5 merge even though protected main is the exact required
  merge commit.
- The pinned MCP repository has no root NOTICE at the frozen commit. Its LICENSE records a transition:
  specification contributions are Apache-2.0, unrelicensed contributions may remain MIT, and ordinary
  documentation is CC-BY-4.0.
- The pinned source schema blob is 180,695 bytes and hashes to
  `9281c4890630e2d1e61792fa23b4084c4ea360cd58519610cd050545ab7b8708`.
- The first Windows baseline bootstrap passed formatting/lint/typecheck and 576 tests before the unchanged
  symlink fixture failed in test setup with `EPERM`. Infrastructure verification cannot use fixed port
  55432 while operator container `sdar-rc2-test-db` owns it; that container was not modified.
- Frozen HTTP concurrency required response IDs to be derived from each request in contract doubles;
  fixed IDs correctly fail the client's stateless response-correlation guard.
- Frozen MRTR cannot reuse the Legacy exact-all-keys response normalization: the frozen contract permits
  partial answers and requires unknown, answered and superseded keys to be ignored without another update.
- Cancellation transport support is not a Frozen readiness attribute; `task_notifications` replaces the
  old package-level `cancellation:task_cancel` requirement while cancellation remains a standard method.
- Provider-side producer queue overflow and authorization-at-send require the local Provider component;
  Phase 7 proves the client contract while Phase 10 must prove those server-side cases before acceptance.
- The default integration launcher owns fixed Compose coordinates and cannot safely run while operator
  services occupy them. Phase 8 Repository verification reused isolated PostgreSQL port 55442 and created
  a disposable test database without mutating any operator container.
- Phase 9 Repository verification passed 58/58 against isolated port 55443. The disposable
  `sdar-codex-phase9` project was preserved while cleanup approval was unavailable, then its containers,
  network and volumes plus the temporary interop archive were safely removed on 2026-07-22.
- Frozen notification reconnect remains an explicit Management operation boundary. Phase 10 composed the
  subscription runtime with active-binding authorization, post-Ack reconciliation and polling fallback.
- The complete integration suite exposed a plan-preparation timing race in restart acceptance; waiting for
  the authoritative A2A state made both Legacy and Frozen restart cases stable without changing Runtime
  semantics. Full E2E similarly exposed that post-commit enhancement warnings are intentionally async;
  the test now waits for their durable projection instead of racing it.
- The v1.1 demo runner previously described operator-managed infrastructure but always started Compose.
  `SDAR_ACCEPTANCE_USE_EXISTING_INFRA=true` now makes that evidence path explicit and never starts or
  stops the caller-owned PostgreSQL/Redis services.
- The external Provider's own 74/74 component report did not detect four cross-client wire mismatches:
  missing Availability `reservationMode`, MRTR/terminal payloads embedded in CreateTaskResult, and
  non-identical get/Notification projections at one Runtime Revision. Strict SDAR validation exposed them.
- The dependency recreation incident was recoverable with an approved frozen install. The restored tree
  exposed three independent time/host-sensitive test gaps: Windows file-symlink privilege in the fixture,
  missing self-managed infrastructure ownership in the Frozen migration verifier, and fixed July 19 Mock
  Task/Availability timestamps. Cross-platform fixtures, explicit infrastructure lifecycle and startup-
  relative Mock timestamps close them; the full self-managed gate now passes 648 tests plus all later stages.

## Idempotence and Recovery

Protocol generation verifies pinned hashes before replacing generated files. Migration 0107 supports empty,
0106 upgrade, idempotent reapply and fail-closed rollback. Frozen registration/refresh is transactional and
cannot silently change protocol mode. Re-running observation admission is idempotent by its protocol-specific
dedupe key. No force push, history rewrite, automatic PR merge or operator-container mutation is allowed.
