## Purpose / Outcome

Upgrade SDAR to the clean-slate v1.2.2 product model. A submitted user request becomes a versioned
User Goal completion contract and a validated Skill Goal DAG before any Skill selection. Ready Skill
Goals are scheduled through bounded attempts and the existing immutable Workflow/LangGraph runtime.
Task, Skill Goal and User Goal outcomes are judged independently, and only
`UserGoalPlanController` may project an A2A terminal state.

The same runtime strictly consumes the external Provider Business Events V0.5.2 profile through a
durable PostgreSQL inbox and independent admission/processing cursors. Events and continuity facts are
mapped to local bindings, Skill Goals, User Goal Plans and criteria, then routed through bounded policy,
recovery and plan-revision decisions without replaying completed effects.

## Context and Orientation

- `packages/domain` owns serializable Goal, Skill Goal, attempt, layered outcome, progress, recovery and
  Business Event client/impact models.
- `packages/application` owns planning, validation, scheduling, selection admission, three judges,
  terminal control, recovery coordination and event-impact orchestration.
- `packages/langgraph-runtime` remains the only Workflow executor. A Skill Attempt may create an
  immutable Workflow instance; neither a Skill Goal DAG nor an event handler is a second executor.
- `packages/mcp-adapter` owns Business Events discovery, headers, JSON-RPC/SSE wire parsing and strict
  frozen-schema validation. Wire/SDK types stop there.
- `packages/persistence-postgres` owns the repositories, CAS, Goal serial gate, durable inbox/cursors,
  completed effects and immutable decision evidence.
- `packages/runtime-redis` owns only reconstructable dispatch references. PostgreSQL remains authority.
- `apps/server` composes one process. `packages/management-api` and `apps/console` expose projections and
  bounded actions over the same services.
- The external Provider repository is read-only. Its protocol assets may be vendored with exact commit
  and file hashes; its implementation is never copied or modified.

## Architecture and Interfaces

The normative owner/type/state inventory is frozen in
`docs/25_V1_2_2_USER_GOAL_RUNTIME_DESIGN.md` and ADR-109.

The execution chain is:

```text
AgentTask
→ UserGoalCompletionContract
→ goal_planning model stage
→ SkillGoalPlanValidator
→ immutable UserGoalPlan / Skill Goal DAG
→ SkillGoalScheduler dispatch intent under Goal CAS
→ Skill selection outside the Goal lock
→ SkillExecutionContract / SkillAttempt
→ immutable Workflow Plan / LangGraph execution
→ TaskGoalJudge → SkillGoalJudge → UserGoalJudge
→ UserGoalPlanController terminal commit
```

The Business Events chain is:

```text
strict Discovery/POST-SSE
→ durable inbox admission + admitted cursor
→ independent processing cursor
→ continuity/relation resolution
→ TaskImpactAssessmentService
→ SkillGoalPlanImpactService
→ bounded recovery / handling Skill Goal / incident / plan revision
```

No model call, MCP call, HTTP request or Queue operation occurs while the Goal CAS/serial lock is held.
Every external result is validated data. Completed Effect and Forbidden Replay records constrain every
recovery and revision.

## Discoveries and Surprises

- The v1.2.1 baseline intentionally implements an explicit `legacy_v11 | frozen_v1` dual-protocol
  boundary. v1.2.2 explicitly forbids Legacy product paths, so ADR-108 must be superseded for new product
  behavior; historical compatibility is not retained.
- Existing Workflow/remote Task continuation, exact Frozen MCP Tasks parsing, Skill Usage and
  PostgreSQL terminal transactions are reusable authorities. They must be rebound to Skill Goal/Attempt
  identity rather than replaced.
- The local `.env` points to an unavailable operator database at port 54329 and the operator `sdar`
  database has a historical migration-ledger gap. Baseline verification required the explicit disposable
  `sdar_v122_baseline_20260722` database and Compose port 55432. No operator data was repaired or reset.
- The external Provider worktree moved independently several times during the Goal. Testing therefore
  uses an exact read-only archive of `8a81b1b`; the moving worktree is never an implicit candidate.
- Real interop exposed and closed SDAR-side Management registration, Reset error parsing, retired-stream
  rollover and post-Ack health/reconnect defects. Failed attempts remain in the attempt ledger.
- The unified gate exposed a stale E2E model route, a stale local `.env` port and an obsolete smoke Skill
  fixture. Each was fixed at its owning boundary without weakening assertions.
- A disposable pgvector container proved real database restart persistence and was deleted with its
  volume; operator-managed infrastructure was not restarted.

## Idempotence and Recovery

- Package verification, source/hash checks and reports are read-only and repeatable.
- `db:reset:v1.2.2` will require development/test environment plus an explicit allowed database prefix;
  it must refuse production/unknown targets before issuing destructive SQL.
- Business Event admission is idempotent by Provider/stream/event/sequence identity; admitted and
  processed cursors are independent and monotonic.
- Scheduler dispatch and active attempts use database uniqueness plus CAS. Redis loss is repaired from
  PostgreSQL dispatch intent without replaying a confirmed side effect.
- Replanning creates a new plan/version and uses completed effects/forbidden replay as constraints.
- External Provider failures are reported and never patched in the Provider worktree.
