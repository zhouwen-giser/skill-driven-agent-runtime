# ADR-069: A2A 1.0.1 Compatibility Baseline

## Status

Accepted on 2026-07-13.

## Context

The original SRS is internally inconsistent: most A2A requirement text names 1.0.0, while its glossary and NFR-COMP-001 acceptance text select 1.0.1. The normalized requirement baseline consistently selects the stricter 1.0.1 target. A2A patch versions do not appear on the wire; the negotiated and Agent Card interface version for specification 1.0.1 is `1.0`.

The official JavaScript SDK has not published a stable 1.0 package. Its current 1.0 implementation is `1.0.0-beta.0`. The pinned official TCK validates the HTTP+JSON/MUST surface but embeds a 1.0.0 specification snapshot and still exercises `application/json` response compatibility.

## Decision

- Pin the normative specification to tag `v1.0.1`, commit `3303592588e388e62e0f69f701af531d2f4e3991`, while advertising and negotiating wire version `1.0`.
- Pin the official JavaScript SDK beta exactly to package `1.0.0-beta.0`, source commit `a005d2a118d3c1552ce6ea86b2917f2a9f56fea9`, and keep all SDK models inside the A2A adapter.
- Pin the official TCK to commit `5996b79f9cefa6fc390980e383e358a66fb9e49e` and require 100% compatibility with zero failures/errors for its applicable HTTP+JSON/MUST scope.
- Cover the 1.0.1 patch delta directly in repository contracts: accept and preserve `application/a2a+json`, retain `application/json` compatibility for the pinned TCK, use only the standard TaskStatus values, and return structured unsupported-media errors.
- Make `third_party/a2a-1.0.1-baseline.json` and `pnpm verify:a2a-baseline` the machine-readable evidence gate. The gate must report SDK beta stability and TCK skips; neither may be described as stable-SDK or all-transport conformance.

## Consequences

NFR-COMP-001 can be verified for the V1 HTTP+JSON transport without placing patch `1.0.1` on the wire. JSON-RPC, gRPC, push notification, and undeclared capability tests remain outside the V1 transport scope and stay visibly skipped. A future stable official SDK or a literal 1.0.1 TCK can replace the pins only through dependency intake, contract reruns, and an updated ADR.
